# Word 文書の操作

python-docx で .docx を読み書きし、見た目は PDF にして画像で確かめる。
失敗しやすいのは4点。既定のテンプレートが US Letter で和文フォントも効かない、見た目は1語でも内部で断片に分かれていて置換が当たらない、既存文書のスタイルを無視して書式を直書きする、変更履歴の包み忘れで直した箇所が校閲で見えない。

## 手順

### 1. 中身を把握する

```
python scripts/inspect_docx.py <docx> [--outline] [--out FILE]
```

用紙・余白・使われているスタイル・表や画像の数・コメントと変更履歴の件数・フィールドと、本文（見出しは `#`、箇条書きは `-`、表は Markdown の表）が出る。長い文書は `--outline` で見出しだけ見てから、`--out` でファイルに出して必要な節だけ読む。

`.doc` は読めない（終了コード2）。ユーザーの了承を得て Word か LibreOffice で `.docx` に変換してから扱う。

### 2. 作る・直す

| やること | やり方 |
|---|---|
| 新しく作る | `references/creating.md` を読み、雛形（A4・和文フォント・ページ番号）から始める。社内様式を渡されたらそれを開いて本文だけ入れる |
| 文言を置き換える | `docx_replace.py` で置換する（下記） |
| 段落・表を足す・消す | python-docx で直接編集する。足す段落のスタイルは、前後の段落と同じものを `inspect_docx.py` の出力から選ぶ |
| コメント・変更履歴 | `references/review-markup.md` を読む |
| どれにも当てはまらない（脚注・テキストボックス・差し込み印刷など python-docx が扱わない要素） | 止まり、扱えない要素であることをユーザーに伝え、Word での手作業か作り直しかを確認する。XML を推測で書き換えない |

**既存の文書を直すときの決まり**

- 原本は変えず、別名で保存する
- 書式は既存のスタイルに合わせる。`run.font` で色やサイズを直書きしない。新しい見た目が要るなら、まずユーザーに既存スタイルで足りないか確認する
- 校閲中の文書（`inspect_docx.py` で変更履歴やコメントが1件以上）を直すときは、変更履歴付きで直すかをユーザーに確認する

**文言の置換**

```
python scripts/docx_replace.py <in.docx> <out.docx> --find 旧 --replace 新 [--find 旧2 --replace 新2] [--dry-run]
```

先に `--dry-run` で一致箇所と前後の文字を出し、意図しない箇所に当たっていないか見てから本番を実行する。1つでも見つからない `--find` があると何も書き出さずに終了コード1で止まる。表記ゆれ（全角・半角、スペースの有無）を疑って `inspect_docx.py` の本文で実際の表記を確かめる。

### 3. 見た目を確かめる

作った・直した文書は PDF にして画像で見る。隣の `operate-pdf` スキルのスクリプトを使う（パスはこのスキルのディレクトリからの相対）。

```
python ../operate-pdf/scripts/to_pdf.py <docx> --outdir <作業フォルダ>
python ../operate-pdf/scripts/pdf_to_png.py <作業フォルダ>/<名前>.pdf
```

見るもの: 用紙と余白、和文フォント、見出しの階層、表の列幅とはみ出し、改ページ位置、空の段落や記号だけの行、ヘッダー・フッター・ページ番号。崩れがあれば原因の箇所だけを直して作り直す。周回の上限（3周）と諦め方は `operate-pdf` の「見た目の確認ループ」に従う。

## 完了条件

- 置換は `docx_replace.py` が終了コード0で、`inspect_docx.py` の本文に旧表記が残っていないこと
- 作成・編集したものは、ページ画像に崩れが無いこと。変換エンジンが無く確かめられなかったら（`to_pdf.py` が終了コード3）、その旨をユーザーに伝えたこと
- 変更履歴付きで直したものは、`inspect_docx.py` の挿入・削除の件数が直した箇所の数と合うこと

## 禁止事項

- 原本を上書きすること
- 置換が見つからなかったとき、似た文字列を推測して置き換えること
- 箇条書きの記号（「・」「●」）や段落番号を本文に直接打つこと
- 変更履歴付きで頼まれた修正を、履歴なしで書き換えること

## 参照ファイル

| ファイル | 読むタイミング |
|---|---|
| `references/creating.md` | 新しく文書を作るとき。雛形のコードと落とし穴の表 |
| `references/review-markup.md` | コメントを付ける、変更履歴付きで直す、既存の変更履歴を扱うとき |

## スクリプト

依存は `python-docx`（`pip install python-docx`、コメントを付けるなら 1.2 以降）。無ければ終了コード2で止まるので、導入をユーザーに確認する。

| スクリプト | 用途 | 終了コード |
|---|---|---|
| `scripts/inspect_docx.py` | 構造と本文を Markdown 風に出す | 0 出力した / 1 開けない / 2 引数ミス・`.doc`・依存不足 |
| `scripts/docx_replace.py` | 断片をまたいで書式を保ったまま置換する。本文・表・ヘッダー・フッターが対象 | 0 全件置換 / 1 見つからない語がある（書き出さない。`--allow-missing` で書き出す） / 2 引数ミス・入出力が同じ・依存不足 |

`docx_replace.py` は段落をまたぐ文字列、脚注・テキストボックスの中、削除済みの変更履歴の文字は置換しない。置換後の文字は、一致した範囲の先頭の書式になる。

PDF 化と画像化は `operate-pdf` スキルの `to_pdf.py` と `pdf_to_png.py`（要 `pypdfium2` `Pillow`）を使う。
