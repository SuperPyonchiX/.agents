# デイリーノートへの記録

「後で日記にまとめよう」は起きない。会話の区切りでエージェントが候補を抜き出し、人は承認するだけにする。

勘所は3つ。(1) **抜き出すのは会話に出た事実だけ。** 推測や一般論を足すと日記が嘘になる。(2) **承認なしに書かない。** 自動で溜まる仕組みは、何が書かれたか分からなくなった時点で放棄される。(3) **既存の行を書き換えない。** 追記だけ。テンプレの空欄（`- 睡眠:`）を埋めるのは追記の範囲に含める。

vault と保存先は次のとおり。パスが違う環境では冒頭で確認してから進める。

| 項目 | 値 |
|---|---|
| vault | `D:\Users\ksk01\Documents\Obsidian` |
| デイリーノート | `01_日記/YYYY-MM-DD.md`（`obsidian daily:path` で実際のパスを確認できる） |
| デイリーのテンプレ | `99_テンプレート/デイリー.md`（節は 体調 / トレード / 今日の学び / 雑記） |
| 読書ログ | `02_読書/<書名>.md`。無ければ `assets/templates/reading.md` から作る |

---

## ワークフロー

直列。承認ゲートが1つ。

```
C1 抽出 → C2 提示・承認（ゲート） → C3 追記（スクリプト） → C4 読み戻し報告
```

C2 で承認された行が0件なら C3 を実行せず、その旨を報告して終える。

---

## 手順

### C1: 抽出

会話（今のセッション全体。圧縮後なら要約も含む）を読み、次の節に当たる発言を拾う。

| 節 | 拾うもの | 拾わないもの |
|---|---|---|
| 体調 | 睡眠時間、調子、症状、服薬。ユーザー本人の発言のみ | エージェントの推測（「疲れているようです」） |
| トレード | 裁量の判断と結果、相場観、EA 運用で起きた出来事（採用・停止・事故） | バックテストの数値の羅列（リポジトリ側に正本がある） |
| 今日の学び | 新しく分かった事実、ハマりどころ、判断の根拠になった気づき | 作業内容の羅列（「〇〇を実装した」）。それは git log にある |
| 雑記 | 上のどれにも入らないが本人が残したいと言ったこと | 残したいと言っていないもの |
| 読書 | 書名が出て、感想・引用・読了の言及があるもの | 書名だけの言及 |

書き方の規則:

- 1件1行、40字以内、体言止めか短文。テンプレの `- 睡眠:` `- 調子:` に当たるものは `- 睡眠:6時間` のように**その行を埋める形**にする
- 節ごとに最大3行。多いときは重要な順に絞り、残りは C2 で「他にもある」と示す
- 出典が分かる形にする（会話のどの発言か）。C2 の表に書く
- 該当が1件も無ければ、その節は候補なしとする。**埋めるために薄い内容を作らない**

### C2: 提示・承認（ゲート）

候補を表で提示し、行ごとに承認を得る。

| # | 節 | 追記する行 | 出典（発言の要旨） |
|---|---|---|---|
| 1 | 体調 | `- 睡眠:6時間` | 「6時間しか寝てない」 |
| 2 | 今日の学び | `- effort で出力精度が変わる` | セッション冒頭の検証結果 |

ユーザーは「全部OK」「1と3だけ」「2は文言を〜に」で答える。文言の修正はそのまま反映する。**表を出さずに書き始めない。承認の返答が無いまま C3 に進まない。**

読書の候補は、対象ファイル名（`02_読書/<書名>.md`）と、新規作成か追記かを表に添える。

### C3: 追記（スクリプト）

承認された行だけを `scripts/append_daily.py` で差し込む。節の位置決め・空欄の置換・重複除外・テンプレからの新規作成はスクリプトが行う。

```bash
# デイリーノート。パスは obsidian daily:path の結果か、01_日記/YYYY-MM-DD.md
python scripts/append_daily.py "D:/Users/ksk01/Documents/Obsidian/01_日記/2026-09-06.md" \
  --template "D:/Users/ksk01/Documents/Obsidian/99_テンプレート/デイリー.md" --date 2026-09-06 \
  --section 体調 --line "- 睡眠:6時間" \
  --section 今日の学び --line "- effort で出力精度が変わる"

# 読書ログ。無ければテンプレから作る
python scripts/append_daily.py "D:/Users/ksk01/Documents/Obsidian/02_読書/<書名>.md" \
  --template assets/templates/reading.md --date 2026-09-06 \
  --section メモ --line "- 第3章: 〜という主張"
```

`--section` は直後の `--line` 群に効く。ファイルが無ければ `--template` から作り `{{date}}` を `--date` に置き換える。Obsidian アプリが起動していなくても動く（ファイル直接操作）。

### C4: 読み戻し報告

追記したファイルの該当節を読み戻して提示する。`obsidian daily:read` が使えればそれで、使えなければファイルを直接読む。書いた行数と、承認されたが書かなかった行（重複で除外された等、スクリプトの出力に出る）を報告する。

**完了条件**: 承認された全行がファイル上に存在し、読み戻した内容をユーザーに提示したこと。

---

## 禁止事項

- **承認前に書くこと。** 表を出して返答を待つ
- **会話に無い内容を足すこと。** 推測・一般論・励まし
- **既存の行を書き換える・消すこと。** 追記と空欄の置換のみ。それ以外の変更はこのスキルの範囲外
- **デイリーノートと `02_読書` 以外のファイルに書くこと。** ノウハウとして残す価値があるものは、markdown-doc や obsidian スキルで別途扱う
- **候補を埋めるために薄い行を作ること。** 無いなら「候補なし」

---

## 参照ファイル

このスキルに `references/` は無い。vault のフォルダ規約と記録ルールは vault 直下の `CLAUDE.md` が正本で、書く前にそれを読む。

## スクリプト

```
python scripts/append_daily.py <ノートのパス> [--template <雛形>] [--date YYYY-MM-DD] (--section <節名> --line <行> [--line <行>]...)...
```

`## <節名>` の直下に行を差し込む。同じ節に `- 睡眠:` のような空欄行があり、新しい行がその接頭辞で始まるなら空欄行を置き換える。節の末尾が `-` だけの行ならそれを置き換える。同一の行が既にあれば書かず `SKIP` と出す。節が無ければファイル末尾に節を作る。ファイルが無ければ `--template` から作る（`--template` も無ければ ERROR）。終了コードは 0（書いた・全件 SKIP を含む）/ 1（ファイルを作れない・雛形が無い）/ 2（引数の指定ミス）。依存は標準ライブラリのみ。
