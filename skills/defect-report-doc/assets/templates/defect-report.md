# 不具合報告書 — 〔短い件名〕

| 項目 | 内容 |
|---|---|
| 発行日 | 〔YYYY-MM-DD〕 |
| 対象 | 〔製品・モジュール・バージョン（コミットID）〕 |
| 重大度 | 〔致命 / 重大 / 軽微 と判断根拠を1行〕 |
| 状態 | 〔処置済み / 処置中 / 水平展開中〕 |

## 1. 現象

〔何がどうなったか。観測された事実だけを書く。ログ・症状の抜粋は最小限〕

## 2. 発生条件・再現手順

〔どういう条件で発生するか。再現手順を番号リストで。再現率も書く〕

## 3. 原因

〔直接原因から根本原因へ、因果の連鎖が追える順で書く。
コード片は必要最小限の抜粋にし、パスと行を添える。
事実と推定を書き分け、推定には「〜と推定される（根拠: …）」の形で根拠を付ける〕

## 4. 処置

〔何をどう直したか。修正コミット・修正版の識別子。処置の検証結果（再発防止テストのPASS等）〕

## 5. 流出原因

〔なぜ設計・レビュー・テストの各工程で検出できなかったか。工程ごとに書く。
ヒアリング結果に基づいて書き、未確認のまま創作しない〕

## 6. 再発防止策

〔何を・どの工程に・どう組み込むか。検証可能な形で書く。
例: 「◯◯観点をレビューチェックリストに追加」「◯◯のテストケースを追加（テストID）」。
「注意する」「徹底する」だけの項目を書かない〕

## 7. 水平展開

〔同じ原因パターンが他にないか、どの範囲をどう点検し、結果どうだったか。
未実施なら「未実施（実施予定: …）」と書く〕
