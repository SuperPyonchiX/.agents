# 概要

| 項目 | 内容 |
|---|---|
| 成果物 | 会議の書き起こしテキストから「決定事項」「宿題」「保留」を分けた一覧Markdown |
| 使ったAI・モデル | Claude Code（Opus 5） |
| 所要 | 40分 |
| 日付 | 2026-08-10 |

90分の定例会議の書き起こし（約12,000字、話者ラベルなし）から、翌営業日に配る議事メモを作りたかった。
自分で読み直すと1時間かかるうえ、宿題の取りこぼしが毎回1〜2件あった。

# やったこと

1. 書き起こしをそのまま貼り、「議事メモにして」とだけ指示した（狙い: まず素の出力を見る）
   → もっともらしい要約は出たが、決定事項と「検討したが決まらなかった話」が混ざっていた。宿題の担当者も落ちていた
2. 出力形式を先に固定した。「決定事項 / 宿題 / 保留」の3表に分け、宿題は担当者・期限の列を必須にすると指示
   → 3表には分かれたが、担当者列に「（不明）」ではなく推測で名前が入っていた
3. 「発言に出てこない担当者・期限を推測で埋めることを禁止する。不明なら空欄にし、末尾に不明項目を列挙する」を追加
   → 空欄と不明リストが出るようになり、確認すべき箇所が3件に絞れた
4. 分類の根拠を確かめるため「各行に、根拠となった発言の引用を1文添える」と指示
   → 引用を突き合わせたところ、決定事項1件が実際は保留だったと分かり、その場で直せた
5. 引用列を外して配布用に整形させ、完成とした（狙い: 引用は検算用で、配布物には不要）

# 効いたポイント

- **出力形式を先に固定し、それから中身を作らせた** — 理由: 形式が自由なままだと、決定事項と未決事項が同じ段落に並んでしまう。表の列を先に決めると、埋まらない列が「情報が足りない箇所」として自動的に浮き上がる
- **推測での穴埋めを明示的に禁止した** — 理由: 禁止しないと担当者名や期限をもっともらしく補完する。議事メモでこれをやられると、誤りが確定情報として配布される。空欄のほうが安全である
- **分類の根拠として原文の引用を出させ、あとで外した** — 理由: 引用があると、自分が全文を読み直さなくても分類の当否を検算できる。実際に誤分類を1件見つけられた。配布物には不要なので最後に落とす
- **一発で完成品を狙わず、検算用の中間出力を経由した** — 理由: 40分のうち検算に使ったのは10分ほどで、全文を読み直す1時間より短い。品質の担保を「読み直し」から「突き合わせ」に置き換えられた

# つまずいたこと・避けること

- 最初に「議事メモにして」とだけ投げた → 出力は読みやすいが、決定と未決の境界が溶けていて使えなかった。分類が目的なら、分類の枠を先に渡す
- 話者ラベルのない書き起こしをそのまま渡した → 担当者の特定精度が落ちる。録音ツール側で話者分離を有効にしておくほうが手戻りが少ない

# 再利用プロンプト

```
以下は会議の書き起こしです。議事メモを作ってください。

出力形式:
- 「決定事項」「宿題」「保留」の3つの表に分ける
- 宿題の表は 内容 / 担当者 / 期限 / 根拠となった発言の引用 の4列
- 決定事項・保留の表は 内容 / 根拠となった発言の引用 の2列

制約:
- 書き起こしに出てこない担当者・期限・数値を推測で埋めることを禁止します。
  不明な場合は空欄にし、表の後に「確認が必要な項目」として列挙してください
- 引用は原文のまま1文で、要約しないでください

書き起こし:
[ここに貼る]
```

検算が済んだら「引用列を外して配布用に整形して」と続ける。
