# PowerPoint の操作

python-pptx で .pptx を読み書きし、配置はスクリプトで検査し、見た目は画像にして全スライドを確かめる。
失敗しやすいのは4点。既定のテンプレートが 4:3 で和文フォントも効かない、python-pptx は文字の量に合わせて縮小しないので文字が枠からあふれる、テンプレートのレイアウトを使わず座標を目分量で置いて重なる、1枚に情報を詰め込みすぎる。

## 手順

### 1. 中身を把握する

```
python scripts/inspect_pptx.py <pptx> [--layouts] [--slides 1-3] [--outline] [--full] [--check]
```

スライドの大きさ、非表示スライド、スライドごとのレイアウト名・図形（プレースホルダの番号・位置・文字、グループの中、表のセル）・ノートが出る。`--layouts` はテンプレートのレイアウトと各枠の位置を出す。.potx もそのまま渡せる。

出力を絞る:

- 20枚を超える資料は、まず `--outline`（1枚1行）で全体を見て、必要なスライドだけ `--slides` で開く
- 文字は図形ごとに60字、ノートは120字で切れる。内容を読み取る・要約する依頼では `--full` を付ける
- 読み取り・要約だけの依頼はこの手順で終わる。配置や文字の点検だけの依頼は、一覧を取らずに手順3の `--check` から始める

`.ppt` は読めない（終了コード2）。ユーザーの了承を得て PowerPoint か LibreOffice で `.pptx` に変換してから扱う。

### 2. 構成を決めてから作る

スライドを作る前に、1枚1行で構成（各スライドのタイトルと伝えること）を書き出してユーザーに見せる。直すだけの依頼なら省く。

構成の決まり:

- 1枚で伝えることは1つ。タイトルはその結論を文で書く（「現状」ではなく「不具合は 3 件に減った」）
- 箇条書きは1枚5行まで、1行は全角30字程度まで。説明しきれない分はノートに書く
- 本文の文字は 18pt を下回らせない。入らなければ文字を減らすか、スライドを分ける

作り方:

| 状況 | やり方 |
|---|---|
| テンプレート（社内様式）がある | `open_template()`（.potx も開ける）で開き、`--layouts` で選んだレイアウトから `add_slide` する。フォント・色・大きさは様式に任せ、上書きしない。見本スライドは使い終わったら消す |
| テンプレートが無い | `references/python-pptx-helpers.md` の `widen_to_16x9()` で 16:9 にしてから作り、最後に `set_ja_font()` を当てる |
| 既存の資料を直す | 原本は変えず別名で保存する。スライドを消すのは `delete_slide()` だけを使う（自前で消すと、後で足したスライドと部品名がぶつかって保存したファイルが壊れる）。直すスライドの図形を `inspect_pptx.py --slides N` で確かめ、名前か番号で指定して書き換える |
| どれにも当てはまらない（アニメーション・SmartArt・埋め込み動画など python-pptx が扱わない要素） | 止まり、扱えない要素であることをユーザーに伝え、PowerPoint での手作業か作り直しかを確認する |

.potx の読み込み、スライドの削除・並べ替え、和文フォントの指定、つまずきやすい点は `references/python-pptx-helpers.md` にある。作り始める前に一度読む。

### 3. 検査して見た目を確かめる

```
python scripts/inspect_pptx.py <pptx> --check
python "<operate-pdf-dir>/scripts/to_pdf.py" <pptx> --outdir <作業フォルダ>
python "<operate-pdf-dir>/scripts/pdf_to_png.py" <作業フォルダ>/<名前>.pdf
```

`to_pdf.py` と `pdf_to_png.py` は `operate-pdf` スキルのもの。このスキルの zip に operate-pdf は含まれないので、利用可能なスキル一覧から operate-pdf の実体パスを解決して `<operate-pdf-dir>` を置き換える。未導入なら、使える Office の PDF 出力と画像表示で同じ観点を確かめる。

`--check` は図形一覧を出さず、検査結果だけを出す（`--outline` と併用すると1枚1行の一覧も出る）。出すもの:

| 区分 | 内容 | 終了コード |
|---|---|---|
| 問題 | スライド外へのはみ出し、図形どうしの重なり、空のプレースホルダ。重なりは文字・表・グラフ・画像の枠で見る（回転を含む外接矩形）。画像どうし、同じグループの中どうし、スライドの9割以上を覆う画像は見ない | 1 |
| 注意 | 文字のあふれの疑い（文字数とフォントの大きさからの推定。表のセルは対象外）、18pt 未満の文字（表のセルを含む） | 影響しない |

空のプレースホルダは PDF にも画像にも写らない（編集画面でだけ「クリックしてテキストを入力」と出る）ので、画像では見つからない。`--check` で拾い、文字を入れるか消す。

```
for 周回 in 1..3:
    --check の「問題」と「注意」を出す
    画像を読み、文字のあふれ・欠け・小さすぎる文字・和文の化けを一覧にする。「注意」に出たスライドは特に見る
        1周目は表示される全スライド。2周目以降は直したスライドの画像だけを pdf_to_png.py --pages で出し直して読む
        （レイアウトやマスターを直したら、それを使う全スライド）
    if 「問題」が「意図した重なり」だけ かつ 画像の指摘 0件: break
    該当スライドの該当図形だけを直す（文字を減らす > 枠を広げる > スライドを分ける の順に検討する）
else:
    3周で直らなければ、残っている問題と試したことを報告する。直ったとは言わない
```

- 意図した重なりは、図形の組と理由をユーザーに伝えて了承を得たものに限る。了承を得た組は以後の周回で直さない
- `pdf_to_png.py` は既定で先頭30ページまでしか画像にしない。それより多い資料は `--pages` で分けて出す
- 非表示スライドは PDF にも画像にも出ないので、画像の番号とスライドの番号がずれる。`inspect_pptx.py` の出力の「画像 pN」で対応をとる（PowerPoint・LibreOffice のどちらの PDF 化でも非表示スライドは出ないことを確かめてある）
- 「注意」のあふれは推定で、外れることがある。あふれているかの判断は画像で行う。推定に出なくても画像であふれていれば直す

## 完了条件

- `inspect_pptx.py --check` の「問題」が0件（終了コード0）。残っているのが意図した重なりだけなら、その組と理由をユーザーに伝えて了承を得たこと
- 表示される全スライドの画像に、文字のあふれ・欠け・小さすぎる文字・和文の化けが無いこと。変換エンジンが無く確かめられなかったら（`to_pdf.py` が終了コード3）、構造検査までの結果と「見た目未確認」をユーザーに伝え、完成扱いにしないこと

## 禁止事項

- 原本を上書きすること
- 文字があふれたとき、フォントを 18pt 未満に下げて押し込むこと
- テンプレートがあるのに、フォント・配色・ロゴの位置を独自に変えること
- 画像を見ずに「スライドを作成しました」と報告すること

## スクリプト

依存は `python-pptx`（`pip install python-pptx`）。無ければ終了コード2で止まるので、導入をユーザーに確認する。

`scripts/inspect_pptx.py` の終了コード:

| コード | 意味 |
|---|---|
| 0 | 出力した（`--check` では「問題」なし。「注意」だけなら0） |
| 1 | 開けない、または `--check` で「問題」が見つかった |
| 2 | 引数の指定ミス（`--slides` の書式違い・範囲外を含む）、入力が無い、`.ppt`、または依存不足 |

位置は mm で出る。1 mm 以下のはみ出し・重なりは無視する。

PDF 化と画像化は `operate-pdf` スキルの `to_pdf.py` と `pdf_to_png.py`（要 `pypdfium2` `Pillow`）を使う。
