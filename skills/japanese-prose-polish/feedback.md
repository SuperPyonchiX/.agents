# 指摘ログ（japanese-prose-polish）

このスキルの出力にユーザーが付けた指摘を溜める。**SKILL.md や references/ はここから自動で書き換えない。** 反映するかは人が数件まとめて決める。

## 記録の書き方

末尾に1件1節で追記する。既存の節は書き換えない（「状態」の行だけは反映のときに更新する）。

```markdown
### 2026-10-27 言い換えが硬すぎる
- 状態: 未判定
- 指摘: ユーザーの言い分の要約。短い原文の引用は「」で囲む
- 対象: 何をどう書いたら指摘されたか（例: ルール16で「〜することができます」を「〜し得る」に直した）
- 関係するルール: パターン番号か SKILL.md の節名。どれにも当たらなければ「なし」
- 頻度の見立て: 毎回効く / この文書だけ / 不明
```

- **このリポジトリは公開されている。** 引用は問題の言い回しだけ（20字程度まで）にし、社名・製品名・人名・数値・社内の事情は `[伏せ字]` にする
- 未判定の節と同じ趣旨なら新しい節を作らず、その節に「- 再発: 2026-11-02」の行を足す

## 反映の手順

ユーザーに「指摘を反映して」と頼まれたときだけ行う。`workflow-skill-architect` の「改修時の入口」に沿って進める。

1. 状態が「未判定」の節を一覧にし、1件ずつ「採用（どこをどう直すか）」「見送り（理由）」の案を付けて提示する。再発の行がある節を先に並べる
2. ユーザーが採用を決めた分だけ SKILL.md か references/ を直し、その振る舞いを evals/evals.json のケースに足す
3. evals を全件回し、前回合格のケースが落ちていないことを確かめる
4. 各節の「状態」を「採用（YYYY-MM-DD）」か「見送り（YYYY-MM-DD、理由）」に書き換える
