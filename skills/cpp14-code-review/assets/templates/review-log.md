- 対象: <リポジトリ / モジュール名>

- レビュー範囲: `work/review-scope.json`
- スキャン結果: `work/scan-report.json`

状態が `open` の指摘が1件でも残っている間は完了としない。
`accepted`（逸脱承認）にできるのは**ユーザーの了承を得たときだけ**。自分で承認しない。
`rejected`（スキャン候補の不採用）には、**なぜ違反でないか**を必ず書く。空欄にしない。

### 列の書き方

| 列 | 内容 |
|---|---|
| ID | `RV-<連番3桁>`。**一度振ったら振り直さない** |
| 対象 | ファイルパス。全体に関わる指摘は `全体` |
| 行 | 行番号。範囲なら `42-58`。全体なら `—` |
| 指摘 | **どの基準にどう反しているか。**「わかりにくい」「良くない」は指摘ではない |
| 根拠 | スキャナのルールID（`CAST-001` 等）、外部ツールのチェック名、または `目視 / <観点名>` |
| 確度 | スキャン由来なら `high` / `medium` / `policy`。目視由来は `—` |
| 重大度 | `高`（仕様・安全性に影響）/ `中`（保守性）/ `低`（表記）。`rejected` は `—` |
| 区分 | `差分` / `差分外`。mode が path のときは `—` |
| 状態 | `open` / `fixed` / `accepted` / `rejected` |
| 対応/理由 | `fixed` なら何をしたか。`accepted` なら**なぜ直さないでよいか**。`rejected` なら**なぜ違反でないか** |
