# 撮影済みの映像を編集する

手元の映像を、プロの編集者の手法（カットの優先順位、間の詰め方、ジャンプカットの隠し方、B ロール、J/L カット、
字幕と音量の規格）に沿って切ってつなぎ、配信できる MP4 にする。

勘所は3つ。(1) **EDL（`edl.json`）が正本** — どこを残してどう見せるかはすべて EDL に書き、書き出し・字幕・検査は
そこから作る。秒数を手で別の場所に写さない。(2) **機械で決まることはスクリプト、判断はエージェント、
感覚は人** — 無音の検出・音量・字幕の規則はスクリプトが測って判定し、話の筋・フック・B ロールの置き場は
エージェントが手法の資料に沿って決め、音の聞こえ方と感情の流れは人に試聴で確かめてもらう。
(3) **見られないものを合格にしない** — エージェントは動画を再生できないので、境目の静止画で見られる項目と、
人に聞く項目を分けて記録する。

台本からナレーション付きの動画を新しく作るのは `narrated-video` の担当。このスキルは、すでに撮った映像を編集する。

## ワークフロー

```
E0 準備 → E1 分析 → [E2 文字起こし] → E3 編集計画（承認） → [E4 字幕]
   → [E5 書き出し → E6 検査・自己検査] を最大3周 → E7 試聴（承認） → E8 納品
          ↑______________ E7 の直し（EDL の該当クリップだけ） ______________|
```

| # | 工程 | 出力（`edit/` は作業ディレクトリ） | 委任 |
|---|---|---|---|
| E0 | 準備 | 決めた条件、`edit/` | しない（ユーザーとのやり取り） |
| E1 | 分析 | `edit/analysis.json` | しない |
| E2 | 文字起こし（任意） | `edit/transcript.json` | しない |
| E3 | 編集計画 | `edit/edl.json`（ユーザー承認済み） | しない（ユーザーの承認が要る） |
| E4 | 字幕（任意） | `edit/subs.srt`（校正済み） | しない |
| E5 | 書き出し | `out/<名前>.mp4`（と `.srt`） | しない |
| E6 | 検査・自己検査 | `edit/check_<周>.json`、`edit/sheets/`、`edit/review.md` | 自己検査の B をサブエージェントへ（下記） |
| E7 | 試聴 | 直す箇所の一覧（無ければ空） | しない |
| E8 | 納品 | MP4 と SRT のパス、検査の結果 | しない |

**中断から再開するとき**は、`edit/` にあるものを見て入り直す。下の行から順に当てはめ、最初に当たった行の工程から始める。

| `edit/` の状態 | 入り直す工程 |
|---|---|
| `review.md` があり NG が無く、`out/` に本番の MP4 がある | E7 |
| `edl.json` があり、計画表の承認が会話か `review.md` の冒頭に記録されている | E4（字幕なしなら E5） |
| `edl.json` がある（承認の記録なし） | E3 の手順4（計画表を見せ直す） |
| `analysis.json` がある | E2 |
| どれも無い | E0 |

承認を得たら `edit/review.md` の冒頭に「計画表 承認: <日付>」と1行書く。

作業ディレクトリは素材のあるフォルダの隣に `edit/`、出力は `out/` を作る。素材のファイルは書き換えない。

## 手順

### E0: 準備

1. `ffmpeg -version` と `ffprobe -version` が通ることを確かめる。通らなければ `references/edl-format.md` の冒頭の導入方法を案内して止まる。
2. 次を決める。依頼文から明らかなものは聞かずに決め、決めた値を1行で伝える。

   | 決めること | 選択肢 | 既定 |
   |---|---|---|
   | 素材 | 主素材（話し手・画面録画）と、B ロールに使える素材・BGM | 依頼で渡されたもの |
   | 配信先 | YouTube / ショート（縦型）/ ポッドキャスト / 社内 / 放送 | YouTube |
   | 目安の長さ | 元の何割か、または何分か | 指定なし（無音とフィラーを詰めるだけ） |
   | 字幕 | なし / 別ファイル（SRT）/ 焼き込み | 別ファイル |
   | 文字起こし | faster-whisper（推論はローカル。初回だけモデルの取得に通信が要る）/ 既存の SRT / なし | faster-whisper。入れられなければ既存の SRT、それも無ければなし |

   配信先と EDL の `target` の対応: YouTube・ショート（縦型）は `youtube`、ポッドキャストは `podcast`、社内は `internal`、放送は `broadcast`。

   ナレーションを新しく録る・台本から作る依頼なら、このスキルの対象外と伝えて `narrated-video` を案内する。

3. 配信先から音量の目標（EDL の `target`）を決める。`references/delivery-specs.md` の「音量」を読む。

**完了条件**: 上の表がすべて埋まり、ffmpeg が使えること。

### E1: 分析

```
python scripts/analyze.py <主素材> [<他の素材>...] --out edit/analysis.json
```

表示された「無音 %」が 5% 未満、または 70% を超えるなら、`--noise` の閾値が素材に合っていない。
無音が 5% 未満なら雑音を無音と見なせていないので `--noise -30`、70% を超えるなら小さな声まで無音にしているので `--noise -45` でやり直す（最大2回。それでも外れるならその値で進め、E3 の計画表に書く）。
出力の形は `references/edl-format.md` の「analysis.json」。

**完了条件**: 終了コード 0 で、主素材の発話区間が1個以上あること。

### E2: 文字起こし（E0 で「なし」なら飛ばす）

```
python scripts/transcribe.py <主素材> --out edit/transcript.json --model small
python scripts/transcribe.py <主素材> --out edit/transcript.json --from-srt <既存の字幕.srt>
```

終了コード 2 で faster-whisper が無いと出たら、`pip install faster-whisper` をユーザーに提案する。
入れられなければ既存の SRT で、それも無ければ文字起こし無しで進める（フィラーのカットと字幕は使えなくなると伝える）。
固有名詞の多い素材・精度が要る素材は `--model large-v3` にする（遅い）。

**完了条件**: `edit/transcript.json` があるか、文字起こし無しで進めると決めたこと。

### E3: 編集計画

1. 下書きを作る。

   ```
   python scripts/draft_edl.py edit/analysis.json --out edit/edl.json --transcript edit/transcript.json --target <target>
   ```

   E2 を飛ばしたときは `--transcript` を外す。ショート動画は `--merge-gap 0.2 --pad-out 0.15`、画面録画が主素材なら `--punch-in 1.0`（文字がぼけるため）。
   ショート（縦型）は、できた EDL の `output` を `{"width": 1080, "height": 1920, "fps": 30, "fit": "cover"}` にする。横長の素材が縦に切り抜かれる。
2. `references/editing-principles.md` を読む。`references/self-review.md` の A（素材を読む）を文字起こしに当てる。
3. 下書きの EDL を直す。形は `references/edl-format.md`。
   - フック: 冒頭に置くクリップを決める
   - 削る区間: 脱線・言い直し・繰り返しのクリップを消すか in/out を詰める
   - B ロール: 素材があれば `overlays` に置く。無ければパンチインで隠す
   - J/L カット: 話題・場面が変わる境目に `audio_shift`
   - わざと残す間・跳ね: `note` に理由、跳ねを残すなら `jump_ok`
4. 計画表をユーザーに見せる。列は「#・クリップ（元の秒）・長さ・内容（文字起こしの冒頭）・手を入れたこと」。
   続けて、削った区間の一覧（元の秒・内容・削った理由）と、出来上がりの長さ（元の長さとの比）を出す。
5. 直しの指示があれば、指示された箇所だけ EDL を直して 4 に戻る。3回直しても承認が得られなければ、合意できていない論点を一覧にして、方針（長さ・残す話題）から相談し直す。

**完了条件**: 計画表と削った区間の一覧について、ユーザーの承認を得たこと。

### E4: 字幕（E0 で「なし」なら飛ばす）

```
python scripts/make_subs.py edit/transcript.json edit/edl.json --out edit/subs.srt [--max-chars 16]
```

ショート動画は `--max-chars 12`。数値の根拠は `references/delivery-specs.md` の「字幕」。

1. SRT を通読し、誤変換・固有名詞・数字を直す（`self-review.md` の C-5）。読み方に迷う固有名詞はユーザーに聞く。
2. EDL の `subtitles` に `subs.srt` を、焼き込むなら `burn_subtitles: true` を書く。

E3 に戻って EDL を変えたら、字幕は作り直す（直した文言は上書きされるので、`--out` を別名にして差分を移す）。

**完了条件**: `edit/subs.srt` があり、通読して直したこと。

### E5〜E6: 書き出しと検査（最大3周）

```
for 周回 in 1..3:
    E5: python scripts/render.py edit/edl.json --out out/<名前>.mp4 --preview
    E6: python scripts/check.py out/<名前>.mp4 --edl edit/edl.json --sheet edit/sheets --report edit/check_<周回>.json
          （ショートは --max-chars 12 を足す。E4 と同じ値にする）
        ERROR を読む（意味と直し方は下の表）
        edit/sheets/sheet_NN.png をすべて開き、references/self-review.md の B と C を当てて
          edit/review.md に「## <周回>周目」の節を足して書く（前の周の節は消さない）
        ユーザーに1行で報告する（例「2周目: ERROR 0 件、NG 1 件（c004 の拡大で頭が切れる）」）
    if ERROR 0 件 かつ review.md に NG が無い:
        break
    if 前の周と同じ ERROR・NG が残った:
        同じ直し方を繰り返さない。原因を書いてユーザーに相談する
    ERROR と NG の箇所だけ EDL・SRT を直す（全体を作り直さない）
else:
    3周しても残る → 残った ERROR・NG と試したことを添えて現状を見せ、判断を仰ぐ
```

| ERROR | 直し方 |
|---|---|
| ラウドネス・True Peak | `render.py` を通さずに作った動画を検査していないか確かめる。通しているなら素材の音が割れている可能性をユーザーに伝える |
| 長さのずれ | 検査した動画が今の EDL から書き出したものか確かめる（EDL を直した後に書き出し忘れていないか）。書き出し直してもずれるなら、素材の fps が可変（スマホの撮影）の可能性をユーザーに伝えて相談する |
| 黒画面 | 素材の頭・末尾の黒を含むクリップの in/out を詰める |
| 無音（間延び） | 該当時刻のクリップを詰める。わざと残した間なら `--max-silence` を上げて検査し直し、理由を `review.md` に書く |
| 字幕の各項目 | SRT の該当の字幕を直す（分ける・要約する・時刻をずらす） |
| 上のどれでもない ERROR、`render.py` の終了コード 2・3 | 表示されたメッセージを添えてユーザーに相談する。推測で EDL を大きく変えない |

WARN は読んで判断し、残すなら理由を `review.md` に書く。

**完了条件**: `check.py` が終了コード 0、`review.md` に NG が無いこと。「不明」の項目は E7 へ持ち越す。

### E6 の自己検査をサブエージェントに渡す

サブエージェントが使える環境では、`self-review.md` の B（境目の画像）の判定はサブエージェントに渡して実行する。
渡すのは `edit/sheets/`（画像と `sheets.md`）、`edit/subs.srt`、`references/self-review.md` のパスだけにし、
EDL・計画表・編集の意図は渡さない（作った側の思い込みを持ち込まないため）。
サブエージェントへの指示には次を含める: `review.md` の書式の表だけを返すこと、ファイルを直さないこと、画像で判断できないものや迷ったものは「不明」にすること。
C（全体）は EDL の意図（`note`）と削った区間の一覧が要るので、自分で当てる。
使えない環境では B も自分で当てる。

### E7: 試聴

1. 本番の書き出しをする（`--preview` を外す）。続けて `check.py` を回し、ERROR が 0 件のままか確かめる。
2. MP4 を `reveal-file` スキルでエクスプローラーに表示し（無ければパスを伝える）、ユーザーに通しで見てもらう。
   `review.md` の「不明」の項目と、`self-review.md` の D を確かめてほしい点として並べる。
3. 直す箇所を、時刻かクリップ id つきで受け取る。直すものがあれば EDL・SRT の該当箇所だけを直し、E5 に戻る。戻ったときの E5〜E6 は新しく1周目から数える（最大3周）。E7 からの戻りは2回まで。超えたら残りを一覧にして相談する。

**完了条件**: ユーザーから「このままでよい」の回答を得たこと。

### E8: 納品

MP4 と SRT のパス、長さ（元の長さとの比）、最後の `check.py` の数値（LUFS・True Peak）を伝える。
B ロール・BGM の利用条件を確かめたかを添える。作業ディレクトリ `edit/build/` が要らなければ消してよいと伝える。

## 禁止事項

- **素材のファイルを書き換える・消すこと。** 出力は `out/`、作業は `edit/` に書く。
- **EDL を通さずに ffmpeg を直接たたいて納品物を作ること。** 検査と作り直しができなくなる。
- **画像で見られない項目（音・動き・感情）を OK にすること。** `review.md` に「不明」で残し、人に聞く。
- **ユーザーに見てもらわずに完成とすること。**
- 利用条件の分からない B ロール・BGM・画像をネットから取ってきて使うこと。
- 計画表の承認前に本番の書き出しをすること（プレビューはよい）。

## スクリプトと依存

`scripts/` の6本（と内部モジュール `ffutil.py`）は Python 標準ライブラリと ffmpeg / ffprobe だけで動く。
例外は `transcribe.py` の既定の動きで、外部パッケージ **faster-whisper** を使う（無ければ終了コード 2 で導入方法を出す。`--from-srt` なら不要）。
呼び出し方・引数・終了コードの一覧は `references/edl-format.md` の「スクリプトの呼び出しと終了コード」。
