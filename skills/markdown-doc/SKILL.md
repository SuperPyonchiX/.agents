# Markdown 文書作成スキル

業務用の Markdown 文書を4種別の定型で作る。仕事の中心は**種別を1つに決めること**で、決まった後の手順は種別ごとの参照ファイルにある。種別を取り違えると読者に合わない文書になるので、迷ったら1問だけ聞いて確定させる。

## 種別の判定

**読者に何をさせたいか**と**主語が誰か**で決める。

| 依頼の主眼 | 種別 | 読む参照ファイル | 例 |
|---|---|---|---|
| 読者に**理解**させる（概念・仕組み・制度・背景・設計思想） | 説明資料 | `references/explanation.md` | 「スクラムの考え方をまとめて」「認証基盤の仕組みを説明して」 |
| 読者に**作業を再現**させる（操作・コマンド・設定を順に実行させる） | 手順書 | `references/procedure.md` | 「VPN接続のやり方をまとめて」「デプロイ手順を書いて」 |
| **自分が実際にやったAI活用**を再現可能に残す | AIノウハウ記録 | `references/ai-knowhow.md` | 「今のやり方をノウハウに残して」「さっきの進め方を記録して」 |
| **原因が特定済みの不具合**を標準章立てで報告する | 不具合報告書 | `references/defect-report.md` | 「不具合報告書を書いて」「この解析結果を報告書にして」 |

- 「まとめて」「ドキュメント化して」は説明資料と手順書の両方に取れる。**どちらが目的か1問だけ聞く。** 答えが得られなければ説明資料として進め、その旨を明示する
- 理解と再現の両方が必要なら1本にまとめず、**2本に分けて相互リンクする**。両方を1本に書くとどちらの読者にも読みにくい
- 原因が未特定の不具合は不具合報告書の対象外。原因究明（C/C++ なら cpp14-defect-analysis）が先だと伝えて止まる
- 会話中にその場で図を1枚出すだけなら、このスキルではなく show-me を使う

**完了条件**: 種別が1つに決まり、対応する参照ファイルを読んだこと。読む前に文書を書き始めない。

## 全種別に共通するルール

参照ファイルの手順に加えて、次を守る。

- **文書タイトルの見出しを付けない。** ファイル名で判別できる。文書は最初のセクション見出しから始める
- **常体（である調）で書く。** 「です・ます」は使わない
- **確認していないことを断定しない。** インプット資料・ヒアリング・実行結果のいずれかに基づかない数値・日付・固有名詞・コマンド・パスを書かない。確認できないまま残す箇所は未確認であることを文書上に明示する
- **プレースホルダーは角括弧**（`[対象サーバー]`）。山括弧は HTML タグとして消える掲載先がある
- **リンクは通常の Markdown リンク記法**。`[[記事名]]` の wikilink は Confluence や GitLab Wiki で機能しない
- **すでに会話に出ている項目は質問しない。** 会話から抽出して「〇〇と理解した」と確認提示し、足りない項目だけを聞く。1ターンの質問は最大3つ
- **提示前に `japanese-prose-polish` を当てる。** 説明資料・手順書・不具合報告書は業務文書モード、AIノウハウ記録は個人発信モード。見出し体系・コードブロック・mermaid のラベル・引用したやり取りは書き換え対象外として渡す
- **完成品ではなくドラフトとして提示する。** 修正依頼への対応は上限3周。収束しなければ食い違いを整理して方針を確認する

## 参照ファイル

種別が決まったら該当する1つだけを読む。全部読まない。

| ファイル | 読むタイミング |
|---|---|
| `references/explanation.md` | 種別が説明資料のとき。ヒアリング項目、章立て、mermaid 選択基準、チェックリスト |
| `references/procedure.md` | 種別が手順書のとき。3フェーズのヒアリング、章立て、完了条件・戻し方の書き方、チェックリスト |
| `references/ai-knowhow.md` | 種別がAIノウハウ記録のとき。会話履歴からの素材抽出、蒸留の基準、索引への追記、検証ループ |
| `references/defect-report.md` | 種別が不具合報告書のとき。章ごとの材料の仕分け、ヒアリングの仕方、禁止事項 |

## テンプレート

各参照ファイルが指示するタイミングで読む。

| ファイル | 種別 |
|---|---|
| `templates/explanation-standard.md` | 説明資料（単発・配布用） |
| `templates/explanation-knowledge-base.md` | 説明資料（Confluence 等へ投稿する記事） |
| `templates/procedure.md` | 手順書 |
| `templates/knowhow.md` | AIノウハウ記録の本体 |
| `templates/knowhow-index.md` | AIノウハウ記録の索引（無いときだけ作る） |
| `templates/defect-report.md` | 不具合報告書 |

## スクリプト

AIノウハウ記録の検証ループで使う。他の種別では使わない。

```
python scripts/check_knowhow.py <knowhow.md> [--index <INDEX.md>]
```

必須5節の有無、概要表の4項目、テンプレートのプレースホルダ残り、「効いたポイント」の件数と理由の有無、再利用プロンプトのコードブロック、行数（101行でWARN、141行でERROR）、`--index` 指定時は索引に当該ファイルへのリンクがあるかを機械的に判定する。終了コード: 0=合格（WARN のみも 0）/ 1=ERROR あり / 2=引数の指定ミスまたはファイルが読めない。依存は標準ライブラリのみ。形式しか見ないので、参照ファイルの目視チェックリストと必ず併用する。
