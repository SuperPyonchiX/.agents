# 確認シートで回す実機確認

エージェントが動かせない環境での確認は、ユーザー（またはテスター）との往復になる。1件ずつ聞いて1件ずつ直すと往復が増え、長い一括確認を最後まで流してから全部失敗すると時間が溶ける。このスキルは確認項目を ID 付きのシートにまとめ、**短いスモーク → 本体 → NG だけの再確認**の順で回す。

設計上の勘所は3つ。(1) **スモークを先に分ける** — 数分で終わる最小ケースを先に流し、1件でも NG なら本体を依頼しない。(2) **次の回に載せるのは NG・未実施・未記入と回帰の行だけ** — OK の行を毎回確かめ直させない。切り出しは `scripts/sheet.py` が決定的に行う。(3) **保留はユーザーが決める** — 残件を黙って後回しにしない。

## ワークフロー

```
M0 対象と環境の確定
M1 シート作成（S- スモーク / T- 本体 / R- 回帰）
for 回 in 1..4:
    M2 依頼（その回に実行するのはスモークだけか、本体までか）
    M3 結果の受け取りと集計（sheet.py summary）
    if 完了（NG・未実施・未記入が0件）: break
    M4 NG の切り分けと修正
    M5 次の回のシートを切り出す（sheet.py next）
else:
    4回で完了しない → 残りの NG と試したことを報告して止まる
M6 完了報告
```

| # | 工程 | 出力 |
|---|---|---|
| M0 | 対象と環境の確定 | 何を・誰が・どこで確かめるか、シートの形式 |
| M1 | シート作成 | `work/test-sheet-r1.md`（または `.csv`） |
| M2 | 依頼 | シートと返し方の説明 |
| M3 | 集計 | `sheet.py summary` の結果 |
| M4 | 切り分けと修正 | NG ごとの原因と対応 |
| M5 | 次の回 | `work/test-sheet-r<N+1>.md` |
| M6 | 完了報告 | 最終の集計と保留の一覧 |

## 手順

### M0: 対象と環境の確定

1. 次を確定する。会話から読み取れないものだけ尋ねる。
   - 確かめる対象（機能・版数・ビルド）と、実行する人（ユーザー本人かテスターか）
   - 実行環境（PC・アプリの版・使うデータ）
   - 一括確認1回にかかる時間の目安。**30分を超えるなら、スモークと本体の間でいったん返してもらう**
   - シートの形式。会話で返すなら Markdown、Excel やスプレッドシートで回すなら CSV
2. スクリーンショットが要る項目があるかを決める。要るなら ID をファイル名か本文に入れて添付してもらう。

**完了条件**: 対象・実行者・環境・形式が決まったこと。

### M1: シート作成

1. `assets/templates/test-sheet.md` をコピーして `work/test-sheet-r1.md` を作る。CSV にする場合は同じ列で作る（列は `ID,区分,確認すること,手順,期待結果,結果,メモ`）。
2. 行を書く。
   - **S-（スモーク）**: 1〜3件。数分で終わり、そこで落ちれば本体が無意味になるもの（起動・最初の操作・最小の入力）
   - **T-（本体）**: 確かめたいことを1行1件。まとめてよいのは、同じ手順で続けて見られるものだけ
   - **R-（回帰）**: 以前直した不具合のうち、今回の変更で壊れうるものの最小セット。毎回載る
3. **期待結果は観察できる形で書く**（「正しく動く」ではなく「図に応答メッセージが1本追加され、Output に例外が出ない」）。判定を実行者に委ねない。
4. `python scripts/sheet.py summary work/test-sheet-r1.md` を実行し、終了コード 2 が出ないこと（列・ID・結果欄の形式）を確かめる。

**完了条件**: `sheet.py summary` が終了コード 0 か 1 で、全行の期待結果が観察できる形になっていること。

### M2: 依頼

1. シートを提示する（ファイルならパス）。**スモークの行を先に実行し、1件でも NG ならそこで返す**ことを明記する。
2. 返し方を1文で伝える: 「結果に OK / NG / 未実施 / 保留 を入れ、NG はメモに見えたことを書く」。
3. 2回目以降は、今回のシートに載っているのが NG・未実施・未記入と回帰の行だけであることを添える。

### M3: 結果の受け取りと集計

1. 受け取った結果をシートに反映する。会話に書かれた結果は、エージェントがシートの結果欄とメモ欄に写す。画像は ID と対応づけてメモに書く。
2. `python scripts/sheet.py summary <シート>` を実行する。

   | 終了コード | 次の動き |
   |---|---|
   | 0 | 完了。M6 へ |
   | 1 | NG・未実施・未記入が残っている。M4 へ（`smoke_ng` があればスモークの NG だけを先に扱う） |
   | 2 | シートの形式が崩れている。表示された箇所を直して再実行する |

3. 集計（OK・NG・未実施・保留・未記入の件数）をユーザーに1行で示す。

**完了条件**: 終了コード 0 または 1 で集計が出て、ユーザーに示したこと。

### M4: NG の切り分けと修正

1. NG の行ごとに原因を次の4つに分ける。

   | 原因 | 対応 |
   |---|---|
   | 実装の不具合 | 直す。同じ原因の NG はまとめて1回で直す |
   | シートの誤り（期待結果・手順が間違っていた） | シートを直す。**直したことと理由をユーザーに示して了承を得る**。結果に合わせて期待結果を黙って書き換えない |
   | 環境の問題（データ・版数・設定） | 環境を整える手順を次の回のメモに書く |
   | 再現しない・情報不足 | 何を見れば切り分けられるか（ログの場所・表示の場所）を次の回の手順に足す |

2. **同じ ID が2回続けて NG になったら**、同じ直し方を繰り返さない。前提を疑い、仮説を立て直す。原因の究明が長引くなら、デバッグの手順を持つスキル（あれば）に切り替えることを提案する。
3. 未実施・未記入の行は、理由（時間切れ・前提が満たせない等）を聞く。前提が満たせないなら手順を直す。
4. 残件を保留にしたい場合は、**ユーザーに保留にしてよいか確認し、了承を得た行だけ**結果を「保留」にし、メモに理由を書く。

**完了条件**: 全 NG 行に原因と対応が付き、実装の不具合は修正済みであること。

### M5: 次の回のシートを切り出す

```
python scripts/sheet.py next work/test-sheet-r<N>.md -o work/test-sheet-r<N+1>.md --round <N+1>
```

前回のシートは消さずに残す（経緯の記録になる）。M4 でシートを直した行は、切り出した後のシートにも反映されていることを確かめる。M2 に戻る。

### M6: 完了報告

次を提示する。**都合の悪い項目を省かない。**

- 回数と、最終の集計（OK・保留の件数）
- 保留にした行と、それぞれの理由・了承を得た旨
- 途中で直したシートの誤り
- 確認していない範囲（シートに載せなかった条件・環境）

**完了条件**: 報告を提示したこと。

## 禁止事項

- **スモークが NG のまま本体を依頼すること。**
- **OK の行を次の回に載せること**（回帰の R- 行を除く）。`sheet.py next` を使わずに手で切り出さない。
- **期待結果を、受け取った結果に合わせて黙って書き換えること。** シートの誤りとして示し、了承を得る。
- **ユーザーの了承なしに保留にすること。**
- **確認結果を受け取っていないのに「完了」と報告すること。**
- **NG が1件出るたびに1件ずつ往復すること。** 1回分の結果をまとめて受け取ってから直す。

## スクリプト

`scripts/sheet.py` — M1・M3・M5 で使う。依存は標準ライブラリのみ。

```
python scripts/sheet.py summary <sheet>
python scripts/sheet.py next <sheet> -o <次の回のシート> [--round N]
```

| サブコマンド | 動作 |
|---|---|
| `summary` | 件数、NG・未実施・未記入・保留の ID、スモークの NG（`smoke_ng`）、完了か（`done`）を JSON で出す |
| `next` | NG・未実施・未記入の行と R- の全行を、結果を空にして書き出す。前回のメモは「前回: 」付きで残す。出力の拡張子で Markdown か CSV かを決める |

シートは Markdown の表（最初に `ID` と `結果` の列を持つ表）か CSV（UTF-8、BOM 付き可）。列は `ID` `区分` `確認すること` `手順` `期待結果` `結果` `メモ` の7つが必須。結果欄は OK / NG / 未実施 / 保留 / 空欄のどれか。

| 終了コード | summary | next |
|---|---|---|
| 0 | 全行が OK か保留（完了） | 書き出した |
| 1 | NG・未実施・未記入が残っている | 載せる行が0件（完了済み） |
| 2 | 引数の指定ミス、表が無い、列が足りない、ID の重複、結果欄の値が不正 | 同左 |
