# タスクの分け方

`SKILL.md` の手順3（タスク分割と台帳）と、手順4aでテストを書けないタスクに当たったときに読む。

## 1タスクの大きさ

1タスクは「1つの区切り（既定はステージ、コミットする方式なら1コミット）で、レビューする人が差分を一度に読める」大きさにする。目安は次のとおり。

- 変更は数ファイル、差分は数十〜200行程度に収まる
- 完了条件が1〜3個の判定できる文で書ける
- タスクを終えた時点でテストが全部通り、そこで止めても壊れていない

大きすぎるサインは、完了条件に「〜と〜と〜ができる」と3つ以上の機能が並ぶこと、テストを書く前に設計を決めきれないこと。小さすぎるサインは、1行の変更ごとにタスクが立ち、台帳の更新のほうが手間になること。

## 縦に切る

層（DB・API・画面）ごとに横に切らず、**1つの振る舞いを端から端まで通す単位**で切る。横に切ると、最後のタスクまで動くものが無く、途中で前提の誤りに気づけない。

| 切り方 | 例 | 判定 |
|---|---|---|
| 横に切る | T1 DB のテーブルを作る / T2 API を作る / T3 画面を作る | 避ける。T3 まで何も確かめられない |
| 縦に切る | T1 1件を登録して一覧に出る / T2 空の入力を弾く / T3 100件を超えたらページを分ける | よい。各タスクで動くものが増える |

最初のタスクは、最も単純な正常系を1本通すものにする。エラー処理・境界値・性能はその後のタスクに回す。

## 完了条件の書き方

判定できる文にする。人や時によって判定が変わる語（「きちんと」「適切に」「動くこと」）を使わない。

| 悪い例 | よい例 |
|---|---|
| CSV の取り込みを直す | `tests/test_import.py::test_skip_blank_line` が通る |
| エラー処理を入れる | 存在しないファイルを渡すと終了コード 2 と「ファイルが見つからない」のメッセージを返す |
| 画面を整える | 幅 375px で横スクロールが出ない（ui-visual-verify の台帳で確認） |
| 速くする | 1万行の入力で `time` が 2 秒以内（変更前は 9 秒） |

## 並べる順番

1. テストの仕組みが無ければ、それを入れるタスク（テストランナーの設定と、通るだけのテスト1本）
2. 最も単純な正常系を端から端まで通すタスク
3. 正常系の残り
4. 異常系・境界値
5. リファクタリング（振る舞いを変えないもの。既存のテストが全部通ることが完了条件）

依存するタスクを先に置く。依存しないタスクどうしの順番は、手戻りの大きいもの（仕様の解釈に自信が無いもの）を先にする。

## テストで判定できないタスク

自動テストで完了を確かめられないタスクは、4a の RED の代わりに次の確かめ方を台帳の「完了条件」に書く。

| 種類 | 代わりの確かめ方 |
|---|---|
| Web 画面の見た目 | 変更前の撮影を残し、変更後と同じ条件で撮って比べる。`ui-visual-verify` が使えるならその台帳で閉じる |
| 実機・専用端末・外部の環境でしか動かない | `manual-test-sheet` が使えるなら確認シートでユーザーに依頼する。使えなければ、確認する手順と期待結果を箇条書きにして依頼する |
| 外部サービスとの通信 | 通信部分をモックしたテストを書く。実際の通信の確認はユーザーの了承を得てから行う |
| 振る舞いを変えないリファクタリング | 変更前に既存のテストが全部通ることを確かめ、その件数を変更前の証拠にする。変更後も同じテストが全部通ることを完了条件にする。テストが足りなければ、先に振る舞いを固定するテストを足す別タスクを立てる |
| 設定ファイル・ドキュメントだけの変更 | 読み込み・構文の検査（`--check`、リンター、ビルド）が通ることを完了条件にする |

このとき「証拠」列には、RED の代わりに「変更前の状態」（撮影ファイル、確認シートの ID、検査の出力）を書く。

## 台帳の記入例

```markdown
| ID | タスク | 完了条件 | 状態 | 変更ファイル | 証拠 | コミット |
|---|---|---|---|---|---|---|
| T1 | 空行を読み飛ばす | `test_skip_blank_line` が通る | 完了 | csvcount.py, tests/test_csvcount.py | RED: AssertionError（3行期待で4行）/ GREEN: 18 passed / ruff 0件 / レビュー指摘1件修正 | なし |
| T2 | 文字コードを自動判定する | Shift_JIS の CSV で `test_sjis` が通る | 進行中 | csvcount.py, tests/test_csvcount.py | | なし |
| T3 | 列名の揺れを吸収する | `test_header_alias` が通る | 保留 | | ユーザー判断: 列名の正規表を先に決める（11/27） | なし |
| T4 | 古い取り込み API を消す | 呼び出し元が0件 | 中止 | | 外部から使われていると判明。ユーザー了承済み（11/27） | なし |
```

コミットする方式では、完了タスクのコミット列に短いハッシュ（例 `3f2a9c1`）を書く。

「証拠」列は、後から読んだ人が「本当に実行したか」を判断できる具体さで書く。件数・エラー数・終了コードなど、出力から写した値を入れる。
