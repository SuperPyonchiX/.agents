# CLAUDE.md / AGENTS.md Audit

常時読み込みされる指示ファイルは、1行残らず毎セッションのコンテキストを消費する。このスキルの仕事は「消せる行を見つけて、勝手に消さずに判定を仰ぐ」こと。失敗しやすいのは、(1) 良かれと思って一括で書き換えて運用上の理由がある記述を壊す、(2)「短くする」だけが目的化して発火や安全に効いている指示を削る、の2つ。**適用は必ず1件ずつユーザー判定を経る。**

## ワークフロー

台帳消化型のループ（cpp14-code-review と同型）。

```
対象ファイルを読み、指摘台帳を作る（フェーズ1〜2）
for 各指摘（重要度順）:
    指摘・根拠・修正案を提示し、ユーザー判定を得る
    判定どおりに適用する（削除 / 修正 / スキル切り出し / 維持）
    台帳の状態を更新する
完了条件: 台帳の全件が「クローズ（適用済み or 維持と判定）」になったこと
```

上限はない（件数分で必ず終わる）。ユーザーが「残りは任せる」と言った場合のみ、残件をまとめて適用してよいが、**削除の適用前に削除対象の全文を提示する**こと。

## 手順

### 1. 対象と現状を確定する

対象リポジトリの CLAUDE.md / AGENTS.md / `.claude/` 配下の指示ファイルを列挙し、それぞれの行数と参照関係（@import や「〜を参照」）を把握する。行数を報告し、どのファイルを監査するかユーザーと合意する。

### 2. 検査して台帳を作る

`references/audit-checklist.md` を読み、観点ごとに指摘を拾って台帳にする。

```
| # | 対象（ファイル:節） | 観点 | 指摘 | 提案 | 状態 |
|---|---|---|---|---|---|
| 1 | AGENTS.md: ディレクトリ構成 | 導出可能 | ls で分かる内容の羅列 | 削除 | 未判定 |
| 2 | CLAUDE.md: レビュー手順 | 手順書化 | 12行の手順に育っている | スキル切り出し | 未判定 |
```

台帳を全件提示してから判定ループに入る。**台帳提示前に修正を始めない。**

### 3. 判定ループを回す

重要度順（削減行数が大きい順・誤動作リスクが高い順）に1件ずつ、指摘・根拠・修正案（削除なら削除対象の全文、修正なら before/after）を示して判定を得る。

- 「スキル切り出し」と判定された節は、このスキルの中で切り出しまで行わない。**対象節と切り出し方針をメモにまとめ、workflow-skill-architect で別途作ることを提案**する（切り出し自体は別工程）
- 判定に迷っているユーザーには「維持」を提案する。消して困る指示は戻しにくい

### 4. 結果を報告する

適用完了後、before/after の行数と、削減見積り（1トークン≒0.75語の概算でよい）、切り出し候補として残った節の一覧を報告する。対象が git 管理下ならコミットの要否を確認する。

## 禁止事項

- ユーザー判定を得ずに削除・書き換えを適用すること（台帳作成のための読み取りは自由）
- 発火条件・安全に関わる指示（禁止事項、確認ゲート）を「冗長」として削除提案する際に、その旨のリスク注記を省くこと
- 短さを理由に、根拠を添えず削除を推すこと。1件ごとに「なぜ消しても動作が変わらないか」を書く

## 想定外の扱い

- 指示ファイルが存在しない場合: このスキルの対象外。新規作成は ai-adoption-advisor（導入提案）の領分なので、そちらを案内する
- 監査中に指示ファイル間の矛盾（CLAUDE.md と AGENTS.md で言うことが違う）を見つけた場合: 台帳に「矛盾」として積み、どちらを正とするかの判定を仰ぐ
