# notion-knowhow-page

Notion データベース「DB_ノウハウまとめ」にノウハウ記事ページを1件追加する。
構造は直列で、途中に承認ゲートが1つある。**承認前に Notion へ書き込んではならない。**

```
入力の特定 → DBスキーマ取得 → ページ案の作成 ⇄ 承認ゲート → 投稿 → 検証と報告
                                  （修正指示があれば戻る）
```

## 対象データベース

| 項目 | 値 |
| --- | --- |
| データベース名 | DB_ノウハウまとめ |
| データベース URL | https://rhinestone-bamboo-492.notion.site/20b2ccbf51c28025b81ee87f1afbad02 |
| データソース ID | `20b2ccbf-51c2-804f-9d9a-000bfe60fbca` |

プロパティは次の4つ。書き込んでよいのは `名前` と `カテゴリ` だけ。

| プロパティ | 型 | 扱い |
| --- | --- | --- |
| `名前` | title | 必須。ページタイトル |
| `カテゴリ` | multi_select | 既存の選択肢を優先して1つ以上選ぶ。合うものが無ければ新規を提案してよい（承認後にのみ追加） |
| `Archive` | checkbox | 触らない（デフォルト false のまま） |
| `作成日時` | created_time | 自動設定。書き込み不可 |

## 前提: notion-api スキル（環境変数 NOTION_TOKEN）

Notion への読み書きはすべて `notion-api` スキルのスクリプト
（`skills/notion-api/scripts/` の `notion_query.py` / `md2blocks.py` / `notion_page.py`）で行う。
トークンは環境変数 `NOTION_TOKEN` から読まれ、未設定ならスクリプトが終了コード2で止まり
設定手順を出す。その場合は工程2の時点で作業を中断し、案内をそのままユーザーに伝えること。
**トークンが無いまま代替手段（手動貼り付け用テキストの出力など）で「投稿した」ことに
してはならない。** 代替を出す場合は「未投稿の下書き」であると明示する。

## 工程

### 1. 入力の特定

投稿する内容を次の順で判別する。

1. ユーザーが Markdown ファイルを指定した → そのファイルを読み込む
2. ファイル指定がない → この会話で得た知見・調査結果・作成物の説明を素材とする
3. どちらも無い（会話に素材と言える内容がない） → 何を投稿したいかユーザーに尋ねる

完了条件: 投稿の素材（ファイル内容または会話中の知見）を特定したこと。

### 2. DB スキーマの取得

`notion_query.py schema` に上記のデータソース ID を渡し、`カテゴリ` の**最新の選択肢一覧**を
取得する（本ファイルには写しを置かない。毎回取得した一覧を正とする）。

```bash
python skills/notion-api/scripts/notion_query.py schema --data-source-id 20b2ccbf-51c2-804f-9d9a-000bfe60fbca
```

完了条件: カテゴリ選択肢一覧を取得できたこと。
取得できない（トークン未設定・権限なし・DB が見つからない）場合はここで中断し、状況と対処
（`NOTION_TOKEN` の設定、インテグレーションの DB への接続共有）をユーザーに案内する。
推測でスキーマを補って先へ進むことは禁止する。

### 3. ページ案の作成

素材から次の3点を作る。

- **タイトル**: 内容が一目でわかる名詞句。既存ページの命名傾向に合わせる
  （例: 「Next Design シーケンス図 → PlantUML 出力スクリプト」「Agent Skillsとは」）
- **カテゴリ**: 工程2で取得した既存選択肢から合うものを1つ以上選ぶ。既存に合うものが
  無い場合は新規カテゴリを提案してよい。その際は案に **「（新規）」と明示**し、あわせて
  最も近い既存選択肢も代替として添える。新規選択肢が実際に追加されるのは承認後のみ
- **アイコン**: 内容を表す絵文字を1つ選ぶ（例: スクリプトの話なら 📜、設計の話なら 📐、
  環境構築なら 🔧）。迷ったらカテゴリの主題に合わせる
- **本文**: Markdown（投稿時に `md2blocks.py` でブロックに変換する）。見出し・コードブロック・手順リストで構造化する。
  本文の冒頭にタイトルを重複して書かない（タイトルは `名前` プロパティに入る）。
  Markdown ファイルが素材の場合、先頭見出しがタイトルと重複するなら本文からは除く

本文案ができたら、承認ゲートに入る前に `japanese-prose-polish` スキルを**業務文書モード**で当て、
AIくさい言い回しを除去する。コードブロック、引用、Notion のプロパティ値は書き換え対象外として渡すこと。

### 4. 承認ゲート

タイトル・カテゴリ・アイコン・本文案の**全体**をユーザーに提示し、承認を求める。
カテゴリに新規提案が含まれる場合は、新規であることと代替の既存選択肢を明示すること。

- 完了条件: ユーザーの承認を得たこと
- 修正指示があった場合: 工程3に戻って直し、再提示する
- **承認を得る前に Notion へ書き込むことは禁止する**

### 5. 投稿

承認された本文を一時ファイル（scratchpad）に置き、`md2blocks.py` でブロックに変換してから
`notion_page.py create` で作成する。

```bash
python skills/notion-api/scripts/md2blocks.py --file body.md --out blocks.json
python skills/notion-api/scripts/notion_page.py create \
  --data-source-id 20b2ccbf-51c2-804f-9d9a-000bfe60fbca \
  --properties props.json --blocks blocks.json --icon "<承認された絵文字>"
```

- properties: `名前`（title）と `カテゴリ`（multi_select）のみ。値の JSON の形は
  notion-api スキルの api-guide.md（`skills/notion-api/references/` 配下）に従う。承認済みの新規カテゴリは
  そのまま値として渡せば選択肢に追加される
- 成功すると作成ページの `id` と `url` が JSON で返る。両方控える

### 6. 検証と報告

作成ページを読み戻し、承認内容と一致していることを確認したうえで、ページ URL をユーザーに報告する。

- タイトル・カテゴリ: `notion_query.py query --compact` で該当ページを引いて確認する
- 本文: `notion_query.py blocks --page-id <id>` でブロックを読み戻して確認する

完了条件: 作成ページの URL を提示したこと。
読み戻しで差異があれば、差異の内容を報告して対処（ページ修正）の指示を仰ぐ。

## 禁止事項

- 承認前に Notion へ書き込むこと
- 承認を得ていない新規カテゴリを `カテゴリ` の値として渡すこと（新規は必ず承認ゲートで「（新規）」と明示して承認を得る）
- 既存ページの更新・削除（このスキルは追加専用）
- `Archive` チェックボックスを操作すること
- 投稿に失敗したとき、別のデータベースや通常ページとして作成して完了扱いにすること。失敗はそのまま報告する
