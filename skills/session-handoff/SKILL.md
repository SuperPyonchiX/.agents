# Session Handoff

セッションの記憶を HANDOFF.md 1枚に圧縮して持ち越すスキル。書き出しと再開の2モードがあり、どちらも直列の手順で完結する。失敗しやすいのは (1) 会話ログの要約になってしまい「次に何をするか」が書かれていない、(2) 再開時に HANDOFF.md を鵜呑みにして実際のリポジトリ状態とズレたまま作業する、の2つ。

HANDOFF.md の構造（`assets/templates/HANDOFF.md`）がセッション間のデータ契約。次のセッションは会話履歴を一切持たない前提で、このファイルだけで再開できる内容にする。

## モード判定

| 状況 | モード |
|---|---|
| 「まとめて」「引き継ぎ書を」「ここまでにする」と言われた。またはコンテキスト限界が近い | 書き出し |
| 「HANDOFF.md から再開」「昨日の続き」と言われた。または作業開始時にリポジトリ直下に HANDOFF.md がある | 再開 |
| どちらとも取れない | ユーザーに確認する |

## 書き出しの手順

1. **現状を機械的に確認する。** `git branch --show-current`、`git status --short`、`git log --oneline -5` を実行し、記憶ではなく実際の状態を材料にする。git リポジトリでなければその旨を HANDOFF.md に書く
2. **`assets/templates/HANDOFF.md` をコピーして全節を埋める。** 保存先は作業リポジトリ直下の `HANDOFF.md`。既存があっても**全体を上書き**する（古い引き継ぎを継ぎ足すと矛盾が残る）
3. 埋めるときの基準:
   - 「次の一手」は着手可能な具体度で書く（実行するコマンド、開くファイル、使うスキル名まで）
   - 未完タスクは優先順に並べ、それぞれ完了条件を1行添える
   - ハマった点は「試して駄目だったこと」を含める。次のセッションが同じ穴に落ちるのを防ぐのが目的
   - 会話でしか共有されていない決定事項（ユーザーの指示・合意）は必ず書く。ファイルに残っていない記憶はこのファイルが最後の砦
4. **完了条件: HANDOFF.md がテンプレートの全節を埋めた状態で存在し、内容の要約をユーザーに提示したこと。** 空欄の節を残さない（該当なしなら「なし」と書く）

## 再開の手順

1. リポジトリ直下の `HANDOFF.md` を読む
2. **実際の状態と突き合わせる。** `git branch --show-current`、`git status --short`、`git log --oneline -5` を実行し、HANDOFF.md の「環境」節と比較する
3. 一致していれば、「未完タスク」の先頭から着手する。着手前に「HANDOFF.md を読み込み、◯◯から再開する」と宣言する
4. **ズレていたら（ブランチが違う、想定外のコミットや未コミット変更がある）、作業を始めずにズレの内容をユーザーに報告し、指示を待つ。** HANDOFF.md 側が古いのか、別の作業が割り込んだのか、エージェントには判定できない
5. 引き継いだタスクがすべて完了したら、HANDOFF.md の削除を提案する（残すと次のセッションが誤って再開モードに入る）。作業が残ったまま終えるなら、書き出しの手順で HANDOFF.md を更新する

## 出力形式

`assets/templates/HANDOFF.md` が正本。節構成は次のとおりで、**節の追加・削除をしない**（次のセッションが構造を前提に読むため）。

目的 / 完了済み / 未完タスク（優先順・完了条件つき）/ 変更したファイル / 次の一手 / 決定事項 / ハマった点・注意 / 環境

## 禁止事項

- HANDOFF.md に認証情報・トークン・パスワードを書くこと（リポジトリ直下に置くファイルであり、誤コミットのリスクがある）
- HANDOFF.md を git にコミットすること。ユーザーが明示的に求めた場合を除き、コミット対象から外す（必要なら `.gitignore` への追加を提案する）
- 再開時に、HANDOFF.md に書かれていないことを「前のセッションでこうだったはず」と推測で補うこと。書かれていないことは分からないとして、ユーザーに確認する

## 想定外の扱い

- 書き出し時に作業内容が複数リポジトリにまたがる場合: 主となるリポジトリの HANDOFF.md に集約し、他リポジトリのパスと状態を「環境」節に書く
- 再開時に HANDOFF.md が見つからない場合: 再開モードを中止し、何を再開したいのかユーザーに確認する
