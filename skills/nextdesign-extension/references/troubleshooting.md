## 確認の依頼のしかた

「動くか試してください」で投げない。**何を見ればよいかを具体的に書く。**

> 次の手順で確認をお願いします。
>
> 1. `<拡張機能ディレクトリ>` を `%LOCALAPPDATA%\DENSO CREATE\Next Design\extensions\` の下にコピーしてください
> 2. Next Design を**再起動**してください（起動中にコピーしても反映されません）
> 3. リボンに「My Extension」タブが出ているか確認してください
> 4. 「検査する」ボタンを押してください。`検査が完了しました` というダイアログが出れば成功です
> 5. 表示 > 出力 で出力ウィンドウを開き、**System カテゴリ**と `MyExtension` カテゴリに何か出ていないか確認してください
>
> 3〜5 の結果を教えてください。エラーが出ていた場合は、その文面をそのまま貼り付けてください。

**出力ウィンドウの System カテゴリを必ず見てもらう。** C# のコンパイルエラーはここにしか出ない。

## 症状別の切り分け表

| 症状 | 原因の所在 | 次にすること |
|---|---|---|
| Next Design 自体が起動しない | マニフェストまたはスクリプト | 下節の切り分け手順。**最優先で対処する** |
| リボンにタブが出ない | マニフェスト（E2） | `extensionPoints.ribbon` の構造、`id` の重複、`orderBefore` の参照先を確認する |
| タブは出るがボタンが無い | マニフェスト（E2） | `groups` と `controls` の入れ子、`type` の綴りを確認する |
| ボタンはあるが押せない（灰色） | マニフェスト（E2） | `isEnabled` の指定、`lifecycle` が `project` でプロジェクト未オープンでないか |
| 押しても何も起きない | スクリプト（E3） | `execFunc` と関数名の一致。System カテゴリにコンパイルエラーが出ていないか |
| 押すと例外ダイアログ | スクリプト（E3） | 例外の文面から特定。`null` 参照が最多 |
| System カテゴリにコンパイルエラー | スクリプト（E3） | 多くは `using` 不足か、存在しない API メンバー |
| イベントが呼ばれない | マニフェスト（E2） | イベント名の綴り、フィルタの `class` 指定。**綴り違いは黙って無視される** |
| 直したのに変わらない | 手順 | Next Design を再起動していない。再起動を依頼する |
| 動作が重い | マニフェスト（E2） | イベントフィルタが `*` になっていないか |

**どれにも当てはまらない症状が出たら、周回を消費せずに止まってユーザーに相談する。** ドキュメントで裏が取れない挙動を推測で直そうとしない。

## Next Design が起動しないとき

**これが最悪のケースで、しかも原因のメッセージが出ない。** 次の順で切り分ける。

1. ユーザーに、拡張機能ディレクトリ内の `manifest.json` を `manifest.json.bak` へ**一時的にリネーム**してもらう
2. Next Design を起動してもらう

   | 結果 | 判断 |
   |---|---|
   | 起動する | 原因は `manifest.json`。E2 に戻る |
   | 起動しない | 原因は他にある。拡張機能ディレクトリごと extensions フォルダの外へ退避してもらい、起動を確認する |

3. `manifest.json` が原因の場合、疑う順に見る。
   - JSON として壊れている（末尾のカンマ、引用符の閉じ忘れ）
   - 必須キー（`name` / `main` / `lifecycle`）の欠落
   - `lifecycle` が `application` になっており、かつスクリプト側に `using` 不足がある
   - そのバージョンに存在しないキーを書いている（`references/doc-map.md` の差異表）
4. 直したら `manifest.json.bak` を元に戻してもらい、再起動して確認する。

**この状態に陥らないために、配置前に必ず `validate_manifest.py` を通す。** 検査項目はここで挙げた原因を潰すために選んである。

`lifecycle` を `application` にしていて起動不能が続く場合、`project` に変えられないか検討する。`project` ならプロジェクトを開くまで読み込まれないので、起動そのものは巻き込まれない。

## 周回のログ

E4 のループは最大3周。**周回ごとに次を残す。** 残さないと、2周目に1周目と同じ直し方をする。

```
## 周回 2
- 症状: リボンにタブは出るが、ボタンを押しても無反応。System カテゴリは空
- 原因の仮説: execFunc "RunCheck" に対して main.cs の関数名が "RunChecks" になっていた
- 加えた変更: main.cs の関数名を RunCheck に修正
- 結果: ボタンは反応するようになったが、例外ダイアログ「オブジェクト参照が...」が出る（周回1とは別の症状）
```

「結果」に**前周との差分**を書く。差分がゼロなら、同じ方針での修正をやめて前提を疑う。

3周して収束しない場合は止まり、次を列挙して報告する。**動いたかのように報告しない。**

- 残っている症状
- 出力ウィンドウの内容（そのまま）
- 周回ごとに試した修正と、その結果
- 疑っているが確認できていないこと
