# AUTOSAR C++14 / CERT C++ 実装ルール

フェーズ1・3で実装方針を決めるとき、フェーズ6でセルフチェックするときに読む。

ここに載せているのは、この工程で実際に判断が要る**頻出ルールの要約**であり、規格そのものではない。プロジェクトが規格文書や静的解析ツール（Coverity / PC-lint / clang-tidy の autosar・cert チェッカ等）を持っている場合は、**そちらが優先**。ツールがあるなら実装後に必ず流し、結果をフェーズ6の報告に含める。

## 判断が分かれる前に確認すること

次の3点はプロジェクトによって方針が違う。設計から読み取れなければ、フェーズ1の開始時にユーザーへ確認する。**推測で決めない。**

1. 例外を使ってよいか（`-fno-exceptions` か）
2. 動的メモリ確保を使ってよいか。使える場合、初期化後も可か
3. 仮想関数・RTTI を使ってよいか（モック化の手段がこれで決まる）

## 型と変換

| 方針 | 補足 |
|---|---|
| C スタイルキャストを使わない | `static_cast` / `const_cast` / `reinterpret_cast` を使い分ける。`reinterpret_cast` は原則禁止で、使う場合は `@note` に理由を書く |
| 整数は固定幅型を使う | `<cstdint>` の `std::int32_t` 等。素の `int` / `long` / `char`（数値用途）を使わない |
| 暗黙の符号変換・縮小変換をしない | 符号付き↔符号なしの混在比較は禁止。必要なら明示キャストし、範囲チェックを先に行う |
| ブレース初期化を使う | `T x{};` で縮小変換をコンパイル時に弾く |
| `bool` を算術に使わない | `if (flag)` は可。`flag + 1` は不可 |
| 列挙は `enum class` を使う | 素の `enum` は暗黙変換するので使わない |

**符号付き整数のオーバーフローは未定義動作**（CERT INT32-C 系）。加減算の前に範囲を検査するか、意図的にラップさせたい場合は符号なし型を使う。

## 初期化とリソース

| 方針 | 補足 |
|---|---|
| 全メンバを初期化する | メンバ初期化子リストまたは既定メンバ初期化子。**未初期化のまま残さない** |
| メンバ初期化子リストの順序を宣言順に合わせる | 宣言順に初期化されるため、ずれると読み違える |
| 変数は使う直前に宣言し、同時に初期化する | 宣言と初期化を離さない |
| リソースは RAII で持つ | 生の `new` / `delete` を対にして書かない。`std::unique_ptr` を使う |
| 所有権のないポインタにスマートポインタを使わない | 参照または生ポインタで表す |

## クラス設計

| 方針 | 補足 |
|---|---|
| 基底クラスのデストラクタは `public virtual` か `protected 非virtual` | 多態的に delete するなら前者 |
| Rule of Five / Zero を守る | デストラクタ・コピー・ムーブのいずれかを書いたら全部を明示する（`= default` / `= delete` を含む） |
| 単一引数コンストラクタは `explicit` | 暗黙変換を防ぐ |
| オーバーライドには `override` を付ける | `virtual` の重複記述はしない |
| 多重継承はインタフェース（純粋仮想のみ）に限る | 実装を持つクラスの多重継承をしない |
| 仮想関数を仮想関数から呼ぶ設計を、コンストラクタ・デストラクタ内で行わない | 派生の実装は呼ばれない |

## 関数

| 方針 | 補足 |
|---|---|
| 例外を投げない関数に `noexcept` を付ける | 組込みでは大半がこれに当たる |
| 副作用のない関数に `const` / `[[nodiscard]] 相当の扱い` | C++14 に `[[nodiscard]]` は無いので、戻り値の無視を許さない旨を `@note` に書く |
| 全経路で戻り値を返す | 到達しないはずの経路も、既定値を返して終える |
| 引数の再代入をしない | 入力引数は読み取り専用として扱う |
| 再帰を使わない | スタック使用量が静的に見積もれなくなる。使う場合は深さの上限を `@note` に書く |
| 可変長引数（`...`）を使わない | 型安全でない |

## 制御構造

| 方針 | 補足 |
|---|---|
| `if` / `for` / `while` の本体を必ずブレースで囲む | 1文でも省略しない |
| `switch` に `default` を必ず置く | `enum class` の全列挙子を書いた場合も置く |
| `case` のフォールスルーを書かない | 意図する場合はコメントで明示する |
| `goto` を使わない | — |
| ループの終了条件を明示する | 無限ループは `for(;;)` と書き、抜ける条件を `@note` に書く |

## 禁止・回避

- `std::malloc` / `std::free` を使わない
- `std::system` / `std::getenv` などの環境依存 API を使わない
- マクロで関数を定義しない（`constexpr` 関数か `inline` 関数にする）
- `NULL` を使わない（`nullptr` を使う）
- `using namespace` をヘッダに書かない
- 未使用の引数は `static_cast<void>` で明示的に捨てるか、引数名を省略する

## テスト容易性との両立

規約とテスト容易性がぶつかる典型と、その解き方。

| ぶつかる点 | 解き方 |
|---|---|
| 仮想関数禁止でモック化できない | テンプレートパラメータで依存を差し替える（静的ポリモーフィズム） |
| 例外禁止で異常系を検証できない | 戻り値のエラーコードで表し、`@retval` に列挙する。それがテスト観点になる |
| 動的メモリ禁止で可変長データを扱えない | 固定長バッファ + 長さで表し、境界値テストの対象にする |
| private をテストしたい | テストしない。public 経由の経路として観点に含める（`references/unit-test-design.md`） |
