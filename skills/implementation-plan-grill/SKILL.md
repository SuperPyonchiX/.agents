# Implementation Plan Grill

実装計画を「質問で潰す」ためのスキル。計画の穴は書いた本人には見えないので、第三者として論点を列挙し、1件ずつ確定するまで先へ進ませないことが仕事。失敗しやすいのは (1) 質問せずに推測で埋めて着工する、(2) 質問を一度に大量にぶつけて回答が薄くなる、(3) 調べれば分かることを質問してユーザーの時間を奪う、の3つ。いずれも下の手順で禁止する。

## ワークフロー

対話ループ（human-in-the-loop）。論点台帳が状態のすべてであり、台帳が空になったら終わる。

```
論点台帳を作る（フェーズ1）
for 巡回 in 1..5:
    未解決の論点から重要度順に1〜3件を選ぶ
    自力で調べて潰せるものは調べて潰す（質問しない）
    残りを推奨回答つきでユーザーに質問する
    回答を台帳に反映する（確定 / 保留 / 新論点の追加）
    if 未解決論点が0件: break（成功）
    if ユーザーが「もう十分」「先に進んで」と言った: break（打ち切り。未解決は保留として記録）
else:
    5巡しても残る論点は「保留」に落とし、リスクとして計画書に明記する
```

新しい論点の追加は3巡目まで。4巡目以降は消化に専念する（際限なく掘ると着工できない）。

## 手順

### 1. 計画を受け取り、材料を読む

入力は実装計画・設計案・修正方針。形式は問わない（会話・Markdown・チケット・口頭の要約）。計画が存在しない（「〜を作りたい」だけ）場合はこのスキルの対象外なので、先に計画の草案を一緒に作るかを確認する。

計画が参照しているコード・設計書・過去の類似実装を**先に自分で読む**。ここを飛ばすと後の質問が的外れになる。

### 2. 論点台帳を作る

計画を次の観点でスキャンし、未解決の論点を台帳にする。台帳は会話に表で提示する（件数が多ければファイルに書き、パスを示す）。

| 観点 | 拾うもの |
|---|---|
| 前提 | 暗黙の仮定。「〜のはず」で書かれている箇所 |
| スコープ | やらないことが明記されているか。膨らむ余地 |
| 入出力契約 | 各工程・関数の入力と出力。境界値の扱い |
| 依存関係 | 変更が波及する先。他の作業・ライブラリとの競合 |
| エッジケース | 空・最大・重複・同時・順序逆転・異常系 |
| 失敗時の挙動 | 途中で失敗したらどうなるか。ロールバック手段 |
| 検証方法 | 完成をどう判定するか。判定可能な形になっているか |

対象が組込みC/C++（割り込み・RTOS・レジスタ・車載規格が絡む）なら、この時点で `references/embedded-probes.md` を読み、観点を追加する。

台帳の形式:

```
| # | 論点 | 観点 | 状態 |
|---|---|---|---|
| 1 | 入力CSVが空のときの挙動が未定義 | エッジケース | 未解決 |
| 2 | 既存のparse系関数と役割が重複しないか | 依存関係 | 未解決 |
```

### 3. 問い詰めループを回す

1巡につき次を行う。

1. 未解決の論点から**重要度順（手戻りが大きい順）に1〜3件だけ**選ぶ
2. コード・資料・git履歴から答えが読み取れる論点は、**質問せず自分で調べて確定**させる。調べた根拠（ファイルパス・該当箇所）を台帳に残す
3. 残った論点をユーザーに質問する。**必ず推奨回答を添える**（「AとBがありえます。過去の類似実装がAなので、Aを推奨します」）。推奨なしの丸投げ質問は禁止する
4. 回答を台帳に反映する。回答から新しい論点が生まれたら追加する（3巡目まで）
5. 台帳の現在状態（確定◯件 / 未解決◯件）を毎巡提示する

### 4. 計画書に固める

未解決論点が0件になったら（または打ち切られたら）、結果を計画書にまとめる。

- 保存先: 元の計画がファイルならそのファイルを更新する。会話上の計画だったら保存先をユーザーに確認する（不要と言われたら会話への提示のみ）
- 構成: 確定した計画本文 / 確定事項（論点と結論の一覧）/ 保留事項（残った論点とリスク）/ 検討して却下した代替案

**完了条件: 計画書（または会話での最終版）を提示し、ユーザーから「これで着工してよい」の合意を得たこと。** 合意前に実装を始めてはいけない。

## 終了条件と失敗時の扱い

- 成功: 未解決論点0件、かつユーザーが最終版に合意した
- 上限: 質疑は5巡まで。新論点の追加は3巡目まで
- 打ち切り: ユーザーが「もう十分」と言ったら残りを保留に落として計画書に明記する。**保留を黙って捨てない**
- 想定外: 質疑の途中で計画の根幹（目的そのもの）が揺らいだら、ループを中断して「計画を作り直すか」をユーザーに確認する。細部の質疑を続けても無駄になる

## 禁止事項

- 問い詰めを省略していきなり実装に入ること
- ユーザーが回答していない論点を、推測で「確定」に変えること
- コードや資料を読めば分かることを質問すること
- 1巡で4件以上の質問をまとめてぶつけること
