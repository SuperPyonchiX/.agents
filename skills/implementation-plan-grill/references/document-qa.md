# 資料起点の Q&A 表

計画ではなく**資料**（要件書・仕様書・議事録・メール・顧客からの依頼文）を入力に、観点表から質問を立て、資料だけを根拠に自分で答え、Q&A 表にまとめる手順。答えを先に資料から探すので、ユーザーや関係者に聞くのは資料で答えられなかった分だけになる。

失敗しやすいのは (1) 資料に書かれていないことを「たぶんこうだろう」と埋めて確定扱いにする、(2) 根拠の箇所を書かずに回答だけ並べる、の2つ。どちらも Q&A 表を読んだ人が誤った前提で動く原因になる。**確定にしてよいのは、資料の該当箇所を示せる回答だけ。**

## 流れ

| # | 工程 | 出力 |
|---|---|---|
| Q1 | 資料の確定 | 資料一覧（名前・種類・分量）と読み方の合意 |
| Q2 | 質問の生成 | 質問台帳（観点つき） |
| Q3 | 資料からの自答 | 台帳に回答・根拠・状態を記入 |
| Q4 | 根拠の検証 | 確定行の根拠が資料に実在することの確認 |
| Q5 | Q&A 表の出力 | Q&A 表ファイルと、要確認・矛盾の一覧 |

## Q1: 資料の確定

1. 資料の一覧（ファイル名・種類・おおよその分量）を作って提示し、**これで全部か**確認する。
2. 読み方を決める。

   | 条件 | 読み方 |
   |---|---|
   | 資料が1〜2件で合計1万字未満 | 自分で全文を読む |
   | 3件以上、または合計1万字を超える | 資料読み込みを外部に任せる手段（NotebookLM など）があり、機密でなければそちらに質問して出典つきで回答を得る。無い、または機密なら自分で分割して読む |

   **機密かどうかは推測で判断しない。** 外部に送る前にユーザーに確認する。
3. Q&A 表の用途を聞く（開発着手前の要件整理か、顧客ヒアリングの準備か、会議の振り返りか）。用途によって Q2 の観点の重みが変わる。

**完了条件**: 資料一覧と読み方に合意を得たこと。

## Q2: 質問の生成

次の観点で、資料を読む人が**着手前に知っておくべきこと**を質問にする。1観点あたり1〜5問、合計30問を上限とする。上限を超えそうなら、手戻りが大きいものを優先して残し、削った観点と件数を Q5 で報告する。

| 観点 | 問うこと |
|---|---|
| 目的 | 何のためにやるのか。成功したと言える状態は何か |
| 利用者・関係者 | 誰が使うのか。誰が決めるのか。誰に影響するのか |
| スコープ | 何をやり、何をやらないのか |
| 入出力 | 何を受け取り、何を返すのか。形式・単位・範囲 |
| 制約 | 期限・予算・既存システム・規格・法規 |
| 非機能 | 性能・信頼性・セキュリティ・保守性の要求水準 |
| 例外・異常系 | 入力不正・障害・想定外の操作のときにどうするか |
| 受入基準 | 何をもって完成・合格とするのか |
| 未決事項 | 資料の中で「検討中」「別途」「TBD」とされているもの |

計画を問い詰めるときの7観点（SKILL.md の手順2）とは別物として扱う。計画がまだ無い段階の資料には、こちらのほうが当てはまる。

**完了条件**: 全観点について質問を立てたか、立てなかった観点に「資料の性質上不要」の理由を書いたこと。

## Q3: 資料からの自答

各質問に、**資料に書かれていることだけ**で答える。状態は次の4つのどれかにする。

| 状態 | 条件 | 根拠欄 |
|---|---|---|
| 確定 | 資料に明記されている | 資料名と箇所（節番号・ページ・行・発言者と時刻）。短い引用を添える |
| 矛盾 | 資料同士、または資料内で食い違っている | 食い違う箇所を両方 |
| 推定 | 明記は無いが、資料の別の記述から強く示唆される | 示唆している箇所。**推定の理由を1行で書く** |
| 要確認 | 資料に手がかりが無い | 空欄。代わりに「推奨回答」を書く（SKILL.md 手順3と同じく、推奨なしの丸投げはしない） |

推定と要確認は、誰かに確かめるまで確定に変えない。

## Q4: 根拠の検証

「確定」と「矛盾」の行について、根拠に書いた引用が資料に**実在するか**を照合する。テキストで読める資料なら文字列検索で確かめる。外部サービスに回答させた場合は、返ってきた出典の本文と突き合わせる。

```
for 周回 in 1..2:
    確定・矛盾の全行について、引用が資料中に見つかるかを確かめる
    if 全行で見つかった:
        break
    見つからなかった行だけを直す（引用を正す / 状態を推定・要確認に下げる）
else:
    2周しても見つからない行は「要確認」に下げ、Q5 で「根拠を確認できなかった」と明記する
```

**完了条件**: 確定・矛盾の全行で引用の実在を確かめたか、確かめられなかった行を要確認に下げたこと。

## Q5: Q&A 表の出力

1. 保存先を確認する。資料と同じ場所か、ユーザーの指定する場所。会話への提示だけでよいと言われたらファイルにしない。
2. 次の構成で書く。

```
# <対象> Q&A 表（YYYY-MM-DD）

資料: <資料一覧>
集計: 確定 N / 推定 N / 矛盾 N / 要確認 N（計 N 問）

## Q&A

| # | 観点 | 質問 | 回答 | 状態 | 根拠 |
|---|---|---|---|---|---|
| 1 | 入出力 | 入力 CSV の文字コードは | Shift_JIS | 確定 | 要件書 3.2「CSV は Shift_JIS で出力する」 |
| 2 | 例外・異常系 | 空ファイルが来たら | （推奨）エラーにして処理を止める | 要確認 | — |

## 要確認（関係者に聞くこと）
## 矛盾（どちらかに決める必要があるもの）
## 質問にしなかった観点と理由
```

3. 要確認が残っていれば、この会話で片づけるか尋ねる。片づけるなら SKILL.md の手順3（推奨回答つきで1回3件まで、3往復まで）に合流する。関係者に持ち帰るなら、要確認の節をそのまま渡せる形にしておく。

**完了条件**: Q&A 表を提示（または保存してパスを提示）し、要確認の扱い（この場で片づける / 持ち帰る）について回答を得たこと。

## 禁止事項

- 資料に根拠の無い回答を「確定」にすること
- 根拠欄に箇所を書かず「資料より」とだけ書くこと
- 機密かどうか確認せずに資料を外部サービスへ送ること
- 質問数を増やすために、答えが自明な質問（資料の表題を聞く等）を立てること
