# ログ出力方針

P2（実装）で読む。実装本体を書くとき、この方針どおりにログを入れる。遵守はゲート2（コードレビュー）で検査する。

## レベル別方針

| レベル | 出力する箇所 | 出力する情報 |
|---|---|---|
| DEBUG | **全関数**の開始と終了。**全メンバ変数**の書き換え箇所 | 開始: 関数名と全引数の値。終了: 関数名と戻り値。書き換え: 変数名と「旧値 → 新値」 |
| INFO | 外部IF（他モジュール・下位API・ハードウェアとの境界）の入出力と、バグ解析の要所（状態遷移・モード切替・初期化完了など）**のみ** | 境界を越えた値、遷移前後の状態 |
| ERROR | **全エラー分岐**（`@retval` の失敗側の成立条件それぞれ） | 何が失敗したかと、原因特定に必要な引数・メンバ変数の値 |

方針の狙い: DEBUG だけで「どの関数にどの値が渡り、内部状態がどう変わったか」を末端まで追跡できること。INFO はフィールドで常時出ていても邪魔にならない量に絞ること。ERROR は追加の再現実験なしに原因を特定できる情報を持つこと。

### DEBUG

- 関数の開始ログには**全引数の値**を入れる。ポインタは null か否か（および指す先の主要な値）を出す
- 関数の終了ログには**戻り値**を入れる。早期 return が複数あっても、どの経路でも終了ログが出るようにする
- メンバ変数を書き換えるすべての箇所で「変数名: 旧値 → 新値」を出す。**`@sideeffect` に書いた状態変化と DEBUG ログは1対1で対応させる**。ログに出ない状態変化があれば、それは `@sideeffect` の漏れか隠れた副作用
- getter のような副作用なしの関数も省略しない（全関数一律）。リリース構成での無効化はログ基盤側（コンパイルスイッチ等）の責任とし、実装側で出し分けない

### INFO

判断基準は「**そのログが無いと、フィールドで起きたバグの解析で何が困るか**」を1文で言えること。言えないなら出さない。DEBUG が無効なリリース構成でも残る前提で、量を絞る。

該当する典型:

- 他モジュール・下位API・ハードウェアへの要求と、その応答（外部IFの入出力）
- 状態遷移・動作モードの切り替わり（遷移前 → 遷移後）
- 初期化・終了処理の完了

### ERROR

- `@retval` の失敗側の成立条件**それぞれ**に対応する分岐で出力する。条件が3つあれば ERROR ログも3箇所
- 「エラーが発生した」だけのログを**禁止する**。どの条件が成立したかと、判定に使った引数・メンバ変数の値を必ず含める（例: 範囲外なら渡された値と上下限、下位API失敗ならその戻り値）
- ERROR ログと戻り値を一致させる。ログだけ出して成功を返す、失敗を返すのにログが無い、のどちらも不整合

## ログAPI の扱い

プロジェクトのログAPI（マクロ名・引数形式・レベル定義）は **P0 のスコープ合意時に確認済み**のものを使う。確認できていないままこの工程に来ていたら、P0 に戻って確認する。

プロジェクトにログ基盤が無い場合は、仮マクロをログ専用ヘッダ（例: `log_stub.h`）に置き、**置換ポイントであることをヘッダの `@note` とコードコメントに明示する**。仮マクロの形式は `LOG_DEBUG(...)` / `LOG_INFO(...)` / `LOG_ERROR(...)` とし、既定では無効（何も出力しない）にしてビルドを通す。

## 記述例

```cpp
bool MotorController::SetSpeed(std::int32_t speed) noexcept
{
    LOG_DEBUG("SetSpeed 開始: speed=%d", speed);

    if ((speed < 0) || (speed > kMaxSpeed)) {
        LOG_ERROR("SetSpeed: speed が範囲外 speed=%d (有効範囲 0..%d)", speed, kMaxSpeed);
        LOG_DEBUG("SetSpeed 終了: 戻り値=false");
        return false;
    }

    LOG_DEBUG("SetSpeed: target_speed_ %d -> %d", target_speed_, speed);
    target_speed_ = speed;

    LOG_DEBUG("SetSpeed 終了: 戻り値=true");
    return true;
}
```

`@sideeffect` に「成功時、target_speed_ を更新する」と書いてあれば、その更新箇所に旧値→新値の DEBUG ログが対応する。外部IFを呼ぶ関数なら、呼び出しと応答の箇所に INFO を足す。

## 禁止事項

- ログ出力に副作用を持たせることを禁止する。ログの引数で状態を変える関数を呼ばない（ログを無効化すると動作が変わる）
- ERROR ログと戻り値の不整合を禁止する（ログだけ出して成功を返す、失敗を返すのにログを出さない）
- ログを理由に `@sideeffect` の記載を省くことを禁止する。仕様は Doxygen、追跡はログ、で役割が違う
- INFO の乱発を禁止する。迷ったら DEBUG に落とす
