# デザイン原則

「図が主役で、タイトルを読めば結論が分かる」スライドにするための原則。構成設計（手順2）の前に一度読み、目視チェック（手順4）でも照合する。

## 1. 1枚の基本構造

上から順に、毎スライド同じ位置に置く。位置が固定されていると、聞き手は2枚目以降「どこを見ればよいか」を探さなくて済む。

```
┌──────────────────────────────────────── n / N ┐  ← ページ番号（右上・薄く）
│ ③ 章名                                         │  ← キッカー: 章番号の丸 + 章名（現在地）
│ 結論を1行で言うタイトル（変化点だけ朱）           │  ← タイトル: 32〜34pt 太字・1行
│                                                │
│      図（本文領域の 7〜8 割）                    │  ← 本文: 図解パターン1つ（+ 右に補足パネル）
│                                                │
│ [今やる1手] 次の行動を1文で                      │  ← 行動帯（章の締めのスライドだけ）
│ ─────────────────────────────────────────── │
│ 出典: …  ・ 画像: …                             │  ← 出典（9pt・灰）
└────────────────────────────────────────────────┘
```

- 余白: 左右 0.65 インチを守る。要素は本文領域（`slidekit.BODY`）の内側に置く。
- 整列: 同じ種類の要素は左端・上端をそろえる。`split_area()` で等分すると自然にそろう。
- 読み順: 左→右、上→下。逆向きに読ませたいときは矢印で誘導する。

## 2. タイトルは結論文にする

タイトルだけを順に読むと話の筋が通る状態にする（「タイトル読み」）。

| 悪い（話題） | 良い（結論） |
|---|---|
| 価格について | Opus 5 の 1/60 の費用で戦えるモデルが出た |
| AI 秘書の比較 | AI 秘書は 3 タイプ — 自分に合う 1 つを選ぶ |
| 現状の課題 | 詰まりは判定の工程に集中していた |

- 1行に収める。34pt で全角 24 字程度が上限。超えるなら言い換える（2行にしない）。
- 型を持つ: 「A から B へ」「X が Y を追い越した」「N で M が揃った」「〜は 3 タイプ」。
- **朱は変化点の語だけ**（`[[語]]`）。1タイトルに1か所。数字（1/60、3 タイプ）か、新しい状態（「選ぶ」「判断」）に付ける。
- キッカー（章名）は名詞句でよい。タイトルと役割を分ける。

## 3. 図が主役、文はラベル

- 1スライド1メッセージ。図解パターンは基本1つ。補足は右サイドの小パネル（`side_panel`）に寄せる。
- 文章で説明しない。図の中の文字は**体言止めの短いラベル**（1要素 15 字以内、2行まで）。
- 文字数の目安: 1スライド 260 字以内（`check_deck.py` が WARN を出す）。超えたら分割する。
- 文字サイズの下限: 本文 13pt、注記 11pt、出典 9pt。読めない文字は置かない。
- 「これまで / これから」の対比は最も強い型。迷ったら Before→After にできないか考える。
- 同じ図の再登場は効く。冒頭の全体像を、まとめで番号付きでもう一度出す。

## 4. 色に意味を持たせる

色は装飾ではなく**分類の記号**。デッキの最初（アジェンダ）で凡例を出し、最後まで変えない。

| 役割 | default theme | 使いどころ |
|---|---|---|
| primary（藍） | 主題・モデル・仕組み | 章番号、見出しの塗り、主要な棒 |
| secondary（碧） | エージェント・工程・運用 | カード見出し、レーン、フロー |
| tertiary（山吹） | コスト・人の側 | 行動帯、価格、補足の強調 |
| accent（朱） | **ここが変わった** | タイトルの強調語、図中の主役 1 つ、転換の矢印 |
| *_soft | 領域の地色 | 枠線の代わりに面で区切る |

- 何色に何の意味を持たせるかは**デッキごとに構成設計で決める**（上の表は既定の割り当て例）。
- 濃い色は見出し・強調だけ。広い面は `_soft` の淡色にする。罫線より面で区切る。
- 朱は図中（タイトル以外）で 1 か所。強調が2つ以上あると、どちらも強調でなくなる。
- 色だけで意味を伝えない。ラベルや凡例を必ず併記する（色覚の個人差・白黒印刷）。

## 5. 数字の見せ方

- 大きな数字 + 小さな単位（`kpi_tiles`、`side_panel`）。数字は 30pt 以上。
- **比較対象を必ず並べる**: 旧価格、中央値、前期。単独の数字は意味を持たない。
- 指数化したら定義を書く（例: 「指数: 10 月公開動画の中央値 = 100」）。基準線（`baseline`）を図に引く。
- 倍率・割合は結論の言葉にする（「2割安く」「中央値の4倍」）。朱のラベルで図の上に置く。
- 棒は 0 始まり。軸を切って差を誇張しない。

## 6. 誠実さの表示

見た目が整うほど、図は「事実」に見える。誤読を防ぐ表示を省かない。

- **概念図タグ**: 数量に基づかない図（勢力図、カーブ、マトリクスの配置）には `tag("概念図")` を付け、必要なら「位置は得意分野の向き（強さの数値ではない）」と注記する。
- **出典**: 全スライドの下に出典を書く。画像・ロゴは「画像: 各社公式」のように出所を書く。
- **要確認タグ**: 裏取りできていない情報は `tag("要公式確認")`。推測で書いた数字には「推定」を付ける。
- 数字・日付・固有名詞は、ユーザーから渡された資料か、確認できた情報源にあるものだけを使う。無いものは作らず、空欄にしてユーザーに確認する。

## 7. 行動に落とす

- 章の最後のスライドに `action_band("…")` を置く（ラベル既定は「今やる1手」）。
- 1文・具体的な動詞で書く: 「普段の作業を 5.5 世代へ切り替え、effort 設定を見直す」。
- 提案・レビュー資料では label を「決めてほしいこと」「お願い」に変える。
- 最後のスライドは「次に見るべき点」か「決めてほしいこと」で締める。「ご清聴ありがとうございました」だけのスライドは作らない。

## 8. デッキ全体の流れ

動向まとめ（月まとめ・20 枚前後）の流れの例:

```
表紙（全体の地図: 変化の番号と代表日）
→ 結論から（勢力図）
→ 期間の俯瞰（スイムレーン）
→ 今日の流れ（アジェンダ + 時間配分 + 色の凡例）
→ 章ごとに: 事実のスライド → 意味のスライド → 今やる1手
→ まとめ（冒頭の図をもう一度 + 番号付き要点）
→ 番外 / 来月見るべき点
```

- 結論を先に出す。聞き手は最初の3枚で「聞く価値があるか」を決める。
- 章の番号と色は表紙・アジェンダ・各章キッカー・まとめで一致させる。
- 発表時間があるなら、1枚あたり 1 分前後を目安に枚数を決め、アジェンダに配分を出す。

## 9. 資料タイプ別の骨組み

構成設計でまずこの骨組みを当て、素材に合わせて増減する。

**動向・ニュースまとめ**
表紙 → 結論（勢力図 `hub_spoke`）→ 俯瞰（`swimlane`）→ アジェンダ → 変化ごとに 2〜3 枚 → まとめ（`numbered_list`）→ 次に見る点（`card_columns`）

**技術説明**
課題（Before→After）→ 全体像（`layer_stack` / `hub_spoke`）→ 仕組み（`flow_steps`）→ 比較（`matrix` / `table`）→ 制約とトレードオフ → 次のアクション

**設計レビュー**
レビューしてほしい論点（1枚目に明示）→ 背景・要件 → アーキテクチャ（`layer_stack`）→ 論点ごとに案の比較（`table` で推奨案を朱）→ リスクと対策 → 決めてほしいこと（`action_band(label="決めてほしいこと")`）

**社内報告・提案**
結論（`kpi_tiles`）→ 現状の数字（`bar_ranking` / `column_compare`）→ 原因（`flow_steps` で詰まりを朱）→ 提案（Before→After）→ 効果とコスト（`column_compare`）→ スケジュール（`gantt`）→ お願い

## 10. やってはいけないこと

- 箇条書きだけのスライド（図にできないなら、そのスライドは不要か、文書で渡す内容）。
- 1枚に図を2つ以上詰める（分割する）。
- 朱を3か所以上に使う。グラデーション・影・3D・クリップアートで飾る。
- タイトルが2行。タイトルと図が別のことを言っている。
- 出典なしの数字。根拠のない数値を「それっぽく」作る。
- 有名キャラクター・他社ロゴを勝手に描き起こす（ロゴ画像はユーザーが用意したものだけ使う）。
