# 目視チェックリスト

検証ループ（手順4）で、`render.py` が出した PNG を見ながら当てる。`check_deck.py` が見られない「見た目」と「中身」を判定する。

**見方**: 自分が作ったものとしてではなく、他人のデッキをレビューする立場で「不合格の箇所」を列挙する。合格の理由を探さない。指摘はスライド番号と項目番号で書く（例: `s5-V3: 右パネルの文字が箱の下端に接している`）。

まず `sheet.png`（一覧）で全体を見て A 項目を当て、次に**全スライドの PNG を1枚ずつ開いて** V 項目を当てる。一覧の縮小画像では小さな文字欠けや表のあふれが見えないので、気になったスライドだけ開く見方はしない。

C 項目（中身）は画像だけでは判定できない。outline.md と素材を手元に置いて突き合わせる。見た目のレビューを別の作業者に依頼したときも、C 項目は依頼元が自分で当てる。

## A. 全体（sheet.png で見る）

- [ ] A1 タイトルだけを順に読んで、話の筋が通る
- [ ] A2 章の番号・色が、表紙・アジェンダ・各章キッカー・まとめで一致している
- [ ] A3 色の意味がデッキを通して変わっていない（同じ色が別の意味で使われていない）
- [ ] A4 文字ばかりのスライド（図が無い・箇条書きだけ）が無い
- [ ] A5 似た見た目のスライドが続きすぎない（同じパターンは 3 枚連続まで）

## V. 見た目（スライドごと）

- [ ] V1 文字が枠・箱・スライドからはみ出していない。切れていない
- [ ] V2 文字同士、文字と線・図形が重なっていない（意図した重ねを除く）
- [ ] V3 箱の中の文字が上下左右の端に接していない（余白がある）
- [ ] V4 不自然な折り返しが無い（1 文字だけの行、単語の途中、括弧だけの行）
- [ ] V5 要素の端がそろっている。等間隔に並ぶべきものが等間隔
- [ ] V6 朱が図中で 1 か所（＋タイトルの強調語）に収まっている
- [ ] V7 一番大きく・濃く見えるものが、そのスライドの主張と一致している
- [ ] V8 本文領域の下半分が空いて間延びしていない／逆に詰まりすぎていない

## C. 中身（スライドごと）

- [ ] C1 タイトルが結論文で、図がその根拠になっている（タイトルと図が別のことを言っていない）
- [ ] C2 数字・日付・固有名詞が、素材（ユーザー提供資料・確認した情報源）と一致している
- [ ] C3 数字に比較対象（旧値・基準・中央値）がある。指数には定義がある
- [ ] C4 定性的な配置図に「概念図」の表示がある
- [ ] C5 出典が書かれている。未確認の情報に「要公式確認」「推定」が付いている
- [ ] C6 章の締めに行動帯（今やる1手 / 決めてほしいこと）がある

## 判定

- 不合格 0 件 → 検証ループ成功。
- 不合格あり → 指摘のあるスライドだけを直す（build_deck.py の該当スライドのブロックだけを編集する）。
- 中身（C 項目）の不合格で、素材が足りず直せないものは、直さずにユーザーへの確認事項として残す。
