# 比較表の素材（架空）

| 観点 | 案A: 全件人手 | 案B: ルール判定＋人 | 案C: 全自動 |
|---|---|---|---|
| 工数 | 全関数を人が読み、期待値とケースを一つずつ確認するため、1関数あたり約2時間かかり繁忙期には滞留する | ルールで機械的に判定できる部分をスクリプトに任せ、人はレビューだけを行うので1関数あたり約30分に収まる | 生成から判定まで自動で回すため人の工数はほぼ不要だが、判定の誤りに気づく仕組みを別に用意しなければならない |
| 見逃しリスク | 担当者の経験に依存し、疲れや思い込みによる見逃しが一定の割合で発生することが過去の不具合から分かっている | 機械判定でばらつきが減り、人は判定結果の妥当性に集中できるため見逃しは案Aより少ないと見込める | 判定ルール自体の誤りがそのまま全件に波及し、誰も気づかないまま出荷される危険が最も大きい |
| 説明責任 | 誰が何を確認したかが記録に残り、監査で説明しやすい | 機械判定のルールと人のレビュー記録の両方が残るため、監査でも説明できる | 判定根拠がツールの内部にしか残らず、監査で説明するための追加資料が必要になる |
