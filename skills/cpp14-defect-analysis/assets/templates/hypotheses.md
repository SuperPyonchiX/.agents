### 列の書き方

| 列 | 内容 |
|---|---|
| ID | `HY-<連番3桁>`。**一度振ったら振り直さない** |
| 仮説 | **何がどうなっているために現象が出るのか。** 「〜が怪しい」は仮説ではない |
| 根拠 | `references/defect-patterns.md` のパターンID（`PTN-INT-001` 等）、差分の該当箇所、観測事実 |
| 確度 | `高` / `中` / `低`。症状の一致、差分の該当、発生条件の一致で上げる |
| コスト | 切り分けコスト。`低` / `中` / `高`。単体テストで再現できる・ログ1行で判定できるものが `低` |
| 順 | 検証順。**確度が高くコストが低いものから**。同順位はコストが低いほうを先に |
| 検証方法 | **実行前に書く。** 何をどこで観測し、どうなれば支持・どうなれば棄却かまで |
| 検証結果 | 観測をそのまま書く。解釈と混ぜない。`rejected` / `deferred` は**なぜそう判断したか**を必ず書く |
| 状態 | `open`（未検証）/ `running`（検証中）/ `confirmed` / `rejected` / `deferred` |

`deferred` は「別の仮説が confirmed になったので検証しなかった」場合に使う。**検証したうえで判断がつかなかったものは `deferred` にせず `open` のまま残す。**

## 検証の履歴

周回ごとに追記する。前周との差分（新しく分かった事実）を必ず書く。差分がゼロの周が2回続いたら、観測手段を変えるかユーザーに相談する。

```markdown
## 周回 1 — HY-001
- 検証方法: 割込み禁止で囲んだビルドと通常ビルドを負荷試験10分×各3回
- 観測: 割込み禁止版 0/3、通常版 3/3 で発生
- 新しく分かったこと: 発生は割込みの有無と相関する。負荷そのものではない
- 判断: confirmed
```
