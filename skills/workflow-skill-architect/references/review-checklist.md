# レビューチェックリスト

スキルを書き終わったら毎回これを当てる。

先に `python scripts/validate_skill.py <スキルディレクトリ>` を実行しておくこと。frontmatter・リンク切れ・孤児ファイル・行数は機械が判定するので、ここでは**機械が見られない項目**に集中する。以下で 🤖 の付いた項目はスクリプトが判定済み、それ以外は目視で当てる。

## frontmatter

- [ ] 🤖 `name` はディレクトリ名と一致しているか
- [ ] `description` に「何をするか」と「いつ使うか」の両方が書かれているか
- [ ] 想定されるユーザーの言い回し（日本語 / 英語）が description に含まれているか
- [ ] 発火してほしい場面を、やや押しつけがましいくらいに書いているか（スキルは使われなさすぎる傾向がある）

## ワークフロー

- [ ] 全体の構造が図または明示的な記述として本文に存在するか
- [ ] 各工程の入力と出力が書かれているか
- [ ] 「構造なしで十分な作業」に、不要なグラフ・状態管理を持ち込んでいないか
- [ ] 指示が命令形で書かれているか（「〜するとよい」ではなく「〜する」）

## ループ

- [ ] ループに **成功条件・上限回数・諦め条件** の3つがそろっているか
- [ ] 評価工程が独立した工程として書かれているか（生成と修正だけになっていないか）
- [ ] 評価はできる限り機械的か（スクリプト / チェックリスト）
- [ ] 修正が「指摘箇所のみ」に限定されているか（毎周の全体再生成になっていないか）
- [ ] 上限に達したときに、未達であることを明示して止まるようになっているか
- [ ] ループ全体をスクリプト化できないか検討したか（修正まで決定的なら、エージェントに回させる理由はない）
- [ ] 評価ループの場合、複数のテストケースをまとめて回す設計になっているか（1件で直すと過学習する）

## グラフ

- [ ] エッジが「順序の都合」ではなく「データ依存」で引かれているか
- [ ] 並列枝の担当範囲が重複しないよう明示されているか
- [ ] 統合ノードに、矛盾時の優先順位と重複の畳み方が書かれているか
- [ ] 条件分岐の表に「どれにも当てはまらない場合」の行があるか
- [ ] 暗黙の巻き戻り（「問題があれば手順2に戻る」）が残っていないか

## 状態・進捗

- [ ] 状態ファイルの更新タイミングが、まとめて最後ではなく各ノードの前後になっているか
- [ ] 再開手順が書かれているか（`done` のスキップ、`running` の再実行、生成物の存在確認）
- [ ] 並列時に同じファイルを複数が書く設計になっていないか
- [ ] ユーザーへの報告の粒度が書かれているか

## データ受け渡し

- [ ] 長い中間結果を会話で渡そうとしていないか（ファイルパス + 形式になっているか）
- [ ] 各ノードの出力形式に**実例**が添えられているか
- [ ] 失敗が型として表現されているか（`status: error` + 理由）
- [ ] 後続に「入力が失敗していた場合の振る舞い」が書かれているか
- [ ] サブエージェントへの指示に「やらないこと」と「迷ったときの振る舞い」があるか

## ファイル構成

- [ ] SKILL.md 本文に、判断に不要な詳細が残っていないか
- [ ] 参照ファイルへのリンクに「いつ読むか」が添えられているか
- [ ] 決定的な処理がスクリプト化されているか
- [ ] 🤖 リンク先のファイルが実在するか
- [ ] 🤖 SKILL.md から一度も参照されていない参照ファイルがないか
- [ ] 🤖 300 行を超える参照ファイルに目次があるか
- [ ] 🤖 `scripts/` のファイルに使い方が書かれているか

## 最終確認

- [ ] このスキルを初めて見るエージェントが、途中で推測を挟まずに実行できるか
- [ ] 想定外の入力が来たときに、無理に進めず止まれるようになっているか
- [ ] スキルの内容が、説明された意図と一致しているか（説明にない副作用を含んでいないか）
